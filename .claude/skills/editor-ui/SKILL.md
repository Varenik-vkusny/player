# Хром редактора: чем пользоваться

Библиотека живёт в `packages/editor/src/ui/`, точка входа — `ui/index.ts`.
Импортируют из неё, а не из файлов по одному:

```tsx
import { Button, Icon, Section } from '../ui/index.js';
```

Расширение `.js` в импорте обязательно и не опечатка: у пакета ESM-резолюция,
и `'../ui/index'` не соберётся.

Оформление всего хрома лежит **одной шаблонной строкой** `EDITOR_STYLES`
в `packages/editor/src/styles.ts`.

Где что лежит (проверено на себе — без этого абзаца первый вопрос был
«а панели-то где»):

| | |
|---|---|
| `packages/editor/src/ui/` | библиотека: `Button`, `Icon`, `Section`, `AlignIcon`, `icons.ts`, `index.ts` |
| `packages/editor/src/panels/` | панели колонок: `ElementList`, `SlidePanel`, `SegmentPanel`, `MarkPanel`, `Inspector`, `StylesPanel`, `ThemePanel` |
| `packages/editor/src/track/` | нижняя зона: дорожка, метки, ветки |
| `packages/editor/src/Editor.tsx` | каркас окна, который всё это расставляет |
| `packages/editor/src/styles.ts` | всё оформление, одной строкой |
| `packages/editor/test/uiChrome.test.ts`, `uiTokens.test.ts` | охрана |

Из `panels/` и `track/` путь до библиотеки — `'../ui/index.js'`,
из `Editor.tsx` — `'./ui/index.js'`.

## 1. Что уже есть

### `Button` — единственная обычная кнопка

```tsx
<Button data-testid="slide-add" onClick={onAdd}>
  Добавить слайд
</Button>
```

Погашенная кнопка с причиной:

```tsx
<Button
  data-testid={`slide-remove-${slide.id}`}
  disabled={!canRemove}
  reason="Нельзя удалить первый или единственный слайд"
  onClick={() => onRemove(slide.id)}
>
  Удалить
</Button>
```

- `type="button"` проставлен сам. Кнопка внутри формы иначе отправляет её.
- `reason` показывается подсказкой **только когда кнопка погашена**.
  Он не обязателен намеренно: на подсказки при наведении не смотрят, и
  видимая строка причины (как у нижней зоны — «Первый слайд вырезать
  нельзя · Буфер пуст») лучше `title`. Есть возможность сказать причину
  видимо — говори видимо, а не через `reason`.
- `className` вызывающего **дописывается** к `ed-btn`, а не заменяет его.
  Он для чужой раскладки (доля во флексе, ширина колонки), не для вида.
- `kind` сегодня ровно один — `'обычная'`. Это **перепись, а не заготовка**:
  у всех 42 обычных кнопок редактора одно оформление. «Главной» и «тихой»
  в продукте не существует, и завести их — значит решить, какая кнопка на
  экране главная. Это вопрос облика: спрашивают владельца, а не выводят
  из перечня.

### `Icon` — единственный значок

```tsx
<Icon name="scissors" />                      {/* рядом с подписью */}
<Icon name="square" label="Остановка" />      {/* без подписи — label обязателен */}
```

- Размер — `1em` от кегля строки, цвет — `currentColor` от её текста.
  Значок следует за текстом, рядом с которым живёт; своих ролей цвета
  и своей ступени кегля у него нет.
- Без `label` значок `aria-hidden`: он сопровождает подпись, а не заменяет её.
  Значку **без** подписи `label` передать обязан вызывающий, иначе кнопка
  останется без имени для тех, кто её не видит.
- `name` — закрытый перечень `IconName = keyof typeof ICON_PATHS`.
  Сегодня в нём: `square`, `scissors`, `chevron-down`, `chevron-right`.

### `Section` — складывающийся заголовок панели

```tsx
<section className="ed-slide-panel" aria-label="Слайды">
  <Section title="Слайды">
    <ul className="ed-slide-list">…</ul>
    <Button data-testid="slide-add" onClick={onAdd}>Добавить слайд</Button>
  </Section>
</section>
```

- `Section` возвращает **фрагмент**, а не свой контейнер: он встаёт ровно
  на место прежнего `<h2 className="ed-insp-title">`, и раскладка панели
  (её `display: flex`, `gap`, потолки списков) остаётся нетронутой.
  Свой контейнер сдвинул бы всех детей на уровень ниже и отобрал бы
  у панели её же `gap`.
- Свёрнутая секция **снимает детей из DOM**, а не прячет их `display: none`.
  Пока содержимое в DOM, оно занимает высоту, где бы ни стояла прокрутка;
  замерено 17.08.2026: несжимаемым секциям правой колонки нужно 890 px,
  а колонка на ноутбуке даёт 368.
- `defaultOpen` по умолчанию `true`. Закрывать секцию молча значит спрятать
  от автора то, что он видел вчера.
- Свёрнутость — свойство показа, а не проекта: она живёт в `useState`
  и в файл не уезжает.
- Имя кнопки собирается как «Свернуть «Заголовок»» / «Развернуть «Заголовок»»
  через `aria-label`. Из подписи оно взяться не может: подпись набрана
  прописными средствами CSS и на слух осталась бы просто названием панели,
  без глагола.

### `AlignIcon` — рисунок из прямоугольников для кнопок выравнивания

```tsx
<AlignIcon shapes={[[2, 3, 4, 18], [8, 6, 12, 12]]} />
```

`Shape` — это `[x, y, width, height]` в поле 24×24. Не значок из набора:
рисунок здесь **данные о раскладке**, а не контур из Lucide.

## 2. Чем пользоваться нельзя, и какой тест это ловит

Все охранные тесты читают **текст исходников**, а не поведение. Обойти их
случайно нельзя, а обойти нарочно — значит вписать себя в список исключений
на виду.

| нельзя | почему | ловит |
|---|---|---|
| `<button className="ed-btn …">` или `ed-action` руками | так и появились 42 одинаковые кнопки при живом запрете плодить своё: копировался класс, а не переиспользовался компонент | `uiChrome.test.ts` → «обычная кнопка не пишется руками» |
| сырой `<svg>` вне `ui/` | второй набор значков расходится с первым молча | `uiChrome.test.ts` → «нет сырых `<svg>` вне ui/» |
| значок символом из шрифта: `▮` `■` `✂` | это буква, а не значок: рисует её шрифт системы, размер и толщина не подчиняются ничему, а на машине без глифа остаётся пустой прямоугольник (ADR-034) | `uiChrome.test.ts` → «значки не рисуются символами из шрифта» |
| контур в `ICON_PATHS`, который нигде не поставлен | набор «на будущее» гниёт молча, потому что его никто не открывает | `uiChrome.test.ts` → «каждый контур из ICON_PATHS хотя бы раз использован» |
| сырой `font-size: 13px` | 48 разных кеглей в 254 местах — так это и накопилось | `uiTokens.test.ts` → «вне блока ролей нет сырых font-size» |
| кегль, спрятанный в сокращении `font:` | то же самое, только незаметнее. `font: inherit` разрешён — размера он не несёт | `uiTokens.test.ts` → «кегль не прячется в сокращении font:» |
| сырой `border-radius: 6px` | | `uiTokens.test.ts` → «вне блока ролей нет сырых border-radius, кроме 50%» |
| сырой цвет `#hex`, `rgb(`, `rgba(` вне блока ролей | | `uiTokens.test.ts` → «вне блока ролей нет сырых цветов» |
| `var(--ui-что-то)`, чего нет в `.ed-root` | **неизвестный токен проваливается МОЛЧА**: объявление отбрасывается целиком, элемент становится `rgb(0,0,0)`, ни ошибки, ни предупреждения | `uiTokens.test.ts` → «каждое упомянутое var(--ui-X) объявлено» |
| объявить роль и не применить | | `uiTokens.test.ts` → «каждая объявленная роль хотя бы раз использована» |

`border-radius: 50%` — **исключение, и его не переводят**: это круг, а не
скругление. Поле, сделанное «очевидно» пиксельным, роняло панель на
эталонной фикстуре, где круг задан через `50%`.

Прогнать обе охраны: `pnpm exec vitest run uiChrome uiTokens`.

**`<button>` внутри `ui/` законен.** Охрана `uiChrome.test.ts` намеренно
не смотрит на файлы самой библиотеки — иначе `Button` и `Section` нельзя
было бы написать вовсе.

### Роли, которыми пользуются вместо сырых значений

Все объявлены в блоке `.ed-root` в `styles.ts`, их 45. Ступени, которые
нужны чаще всего:

- кегли: `--ui-type-xs|s|m|l|xl` (база — `m`);
- межстрочные: `--ui-lh-tight|normal|loose`;
- скругления: `--ui-radius-s|m|l`;
- текст: `--ui-content-fg`, `--ui-content-fg-secondary`, `--ui-content-fg-tertiary`;
- поверхности: `--ui-surface-base|panel|raised|overlay|canvas`;
- линии: `--ui-line`, `--ui-line-strong`, `--ui-line-disabled`;
- фокус: `--ui-focus`, `--ui-focus-ring`.

Точный список — `grep -o -- "--ui-[a-z-]*:" packages/editor/src/styles.ts | sort -u`.
Не помни его, а посмотри: он растёт.

## 3. Как добавить новое

**Кладут в `ui/`, а не рядом с местом применения.** Компонент, положенный
рядом, переиспользовать не станут — его просто не найдут, и через месяц
рядом ляжет второй такой же.

Порядок один и тот же:

1. написать компонент в `packages/editor/src/ui/Имя.tsx`;
2. дописать экспорт в `ui/index.ts`;
3. оформление — в `styles.ts`, только ролями `--ui-*`;
4. заменить **все** нынешние места разом, а не одно «для примера»:
   недоделанная замена оставляет два способа делать одно и то же,
   и это хуже, чем один плохой;
5. прогнать `pnpm exec vitest run uiChrome uiTokens` и `pnpm typecheck`.

**Добавить значок:**

```ts
// packages/editor/src/ui/icons.ts
  /** Зачем он нужен и что был раньше. */
  'chevron-down': '<path d="m6 9 6 6 6-6"/>',
```

Контур берут из Lucide **дословно** — содержимое тега `<svg>`, без оболочки
(`viewBox`, `stroke`, толщина живут в `Icon.tsx` одни на всех). Первоисточник:
`https://raw.githubusercontent.com/lucide-icons/lucide/main/icons/ИМЯ.svg`.
Пакет **не ставится** (ADR-034). Значок заводят **в тот же заход, когда его
ставят**: контур без применения роняет охрану, и это правильно.

**Вид не влезает в закрытый перечень** (`ButtonKind` и любой другой) — это
**находка, а не препятствие**. Её называют вслух и спрашивают, а не
расширяют перечень по дороге: перечень закрыт именно затем, чтобы пятый вид
нельзя было завести молча.

## 4. Правила, купленные сессиями программы

**Сначала перепись, потом унификация.** «84 кнопки» при пересчёте оказались
42 копиями одного класса плюс **42 разными органами в 36 обличьях**:
выбранная плитка приёма, текущий слайд, ручка стыка на дорожке, образец
цвета, кнопка-поле ввода. Слепое слияние «всех кнопок в одну» сняло бы
опознаваемость у сорока двух виджетов. Считай предметы **до** того, как
объявишь их одинаковыми, и считай грепом, а не по памяти.

**Проверь, нет ли у предмета своего заголовка, прежде чем давать ему новый.**
План велел обернуть панели правой колонки в `Section` снаружи. У **семи**
панелей уже был свой `<h2 className="ed-insp-title">`, и обёртка дала бы по
два заголовка на панель плюс двух хозяев одного текста — ровно тот разнобой,
ради конца которого заводится библиотека. Поэтому `Section` заменяет `<h2>`,
а не оборачивает панель. Перед тем как дать предмету обвязку, посмотри
грепом, что у него уже есть.

**Тест, где ожидаемое и полученное берутся из ОДНОГО источника, зелен при
любой реализации.** Сессия 46: проверка «список шрифтов не режет своё же
значение» сравнивала ширину списка с шириной того же списка, распущенного
по содержимому (`select.style.width = 'auto'`). Но режет не сам список,
а потолок `max-width` его **родителя** `.ed-propbar-field` — и
«распущенный» упирался в тот же потолок. Тест сравнивал число с самим
собой, оставался зелёным при возвращённом потолке 168 px и выяснилось это
**сломом, а не рассуждением**. Починка — образец из другого источника:
копия списка в том же родителе (те же кегль, отступы, высота), но
абсолютом и без потолка, то есть вне той тесноты, которую проверяем.
Третий такой случай за программу: к вопросу «что должно сломаться»
добавляй второй — **«откуда взято то, с чем сравниваю»**.

## 5. Помнить всегда

**`styles.ts` — ОДНА шаблонная строка, и обратных кавычек внутри неё нет
ни одной, даже в комментариях CSS.** Одна такая кавычка обрывает строку
и роняет весь бандл редактора.

**Скриншотные эталоны смотрят глазами.** Playwright, не найдя эталона,
пишет `actual` прямо в папку эталонов и роняет тест; перезапуск не глядя
делает их эталонами **молча** — то есть выключает проверку, а не проходит
её. Первый прогон после появления новой фикстуры **обязан** быть красным.
У снимков хрома (`e2e/editor-chrome-shot.spec.ts`) допуск **нулевой**.

**Хром редактора покрыт пикселями только в `editor-chrome-shot.spec.ts`.**
Остальные 120 эталонов снимают сцену и на смену гарнитуры и 64 кеглей
не шелохнулись ни разу. Меняешь вид хрома — этот файл и есть твоя
страховка, других нет.
