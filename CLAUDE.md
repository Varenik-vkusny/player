# Проект

Интерактивные объяснения в вебе. Внешне похоже на видео — озвучка, таймлайн,
анимации. Внутри DOM, поэтому зритель может взаимодействовать.

Автор ставит на таймлайне **гейты** — точки, где плеер останавливается и открывает
взаимодействие. Вне гейтов кликать нельзя физически.

**Известно про будущее: будут ветвления в виде нодов.** Проект перестанет быть
«одна дорожка, одна сцена» и станет графом сегментов: у каждой ноды своя
озвучка и своя сцена, рёбра выбираются ответами на гейтах. Строить это сейчас
не надо. Но **нельзя размазывать доступ к `project.audio` и `project.scene`
по коду** — обращения идут через один узкий слой, иначе переход на граф
станет переписыванием вместо миграции схемы. Подробности:
[`docs/planning.md`](docs/planning.md).

## Команды

```
Установка:      pnpm install
Все проверки:   pnpm check          ← запускать после каждого изменения
Типы:           pnpm typecheck
Юнит-тесты:     pnpm test:unit
Один тест:      pnpm exec vitest run -t "часть названия"
E2E:            pnpm test:e2e
Один e2e:       pnpm exec playwright test -g "часть названия"
Дев-сервер:     pnpm dev            → http://localhost:5173/
Другая фикстура: http://localhost:5173/?fixture=e2e
Сборка плеера:  pnpm build:player   → apps/playground/public/bundle/player.js
Голый HTML:     http://localhost:5173/bare.html
```

`pnpm check` = типы трёх проектов → юниты → сборка плеера → e2e.
Сборка стоит перед e2e не случайно: тесты инварианта №9 проверяют, что
браузер получает собранный файл байт в байт.

Спайки — одноразовая оснастка, в `pnpm check` не входят:

```
Сервер спайков:  pnpm spikes:serve      затем http://localhost:5180/
Часы:            pnpm spike:clocks 600 drift-10min.wav
Таймлайн/гейт:   pnpm spike:timeline s2
Блокировка:      pnpm spike:gate-lock
Паритет рендера: pnpm spike:parity
Производит-ть:   pnpm spike:perf
Квота хранилища: pnpm spike:quota
```

## Инварианты

Это законы. Нарушить можно только через новый ADR и мой явный ответ.
Если код требует нарушить закон — остановись и спроси.

1. **Аудио — единственный источник времени.** Никакой `setInterval`, счётчик
   кадров или отдельный таймер не имеет права двигать сцену. Позиция в аудио
   и есть время проекта. → [ADR-002](docs/adr/ADR-002-time-and-animation.md), S0b
2. **Таймлайн ведомый, не ведущий.** Он создаётся в паузе, никогда не играет
   сам. Каждый кадр мы выставляем ему время, посчитанное от аудио. → S1
3. **Гейт — единственный способ дать интерактив.** Вне гейта у сцены
   `pointer-events: none`. Не «мы не вешаем обработчик», а физически недоступно. → S4
4. **Гейт останавливает всё сразу.** Аудио, таймлайн, время. Возобновление — с
   той же позиции. Перемотки не происходит никогда.
   → [ADR-005](docs/adr/ADR-005-gates.md), S2, S3
5. **Один рендер на редактор и плеер.** Редактор импортирует рендер из плеера.
   Две реализации отрисовки сцены — архитектурная ошибка, а не оптимизация.
   → [ADR-003](docs/adr/ADR-003-render.md), S7
6. **Направление зависимостей:** `editor → player → core`. Обратных импортов нет.
   `core` не знает про DOM и React. → тест инвариантов
7. **Схема версионируется.** Любое изменение схемы = бамп версии + функция
   миграции + фикстура + тест. Без исключений, даже для «мелкого поля».
   → [ADR-004](docs/adr/ADR-004-project-format.md), тест инвариантов
8. **Анимируем только `transform`, `opacity`, `filter`.** Всё остальное уводит
   с композитора и роняет кадры. → перечень закрыт в схеме, S6.
   **Оговорка:** `filter: blur()` не равноправен остальным — измерено, что он
   удваивает длину худшего кадра. На 15 элементах запас есть (58.8 fps при
   пороге 55), но при росте числа блюров он исчезнет первым.
9. **Плеер собирается без фреймворка** в самостоятельный ESM-бандл и открывается
   в голом HTML-файле. → `e2e/bundle.spec.ts`: проверяет отсутствие внешних
   импортов, побайтовое совпадение отданного файла с собранным и работу плеера
   в `bare.html`.
10. **Метки времени привязаны к словам транскрипта, не к миллисекундам.**
    Секунды — только там, где слова нет. → [ADR-008](docs/adr/ADR-008-timeref.md), S5

## Как работать

**Планируй до кода.** Для любой задачи сложнее одного файла — plan mode, план
на согласование, потом код. Открытые вопросы пиши в `docs/planning.md`.

**Гипотезу проверяй на настоящих данных, а не на своей уверенности.** Любое
утверждение вида «эта функция ведёт себя так», «квота примерно столько»,
«библиотека понимает такие имена» — это догадка, пока её не подтвердил прогон
на реальном коде, реальном файле, реальном браузере. Проверять — значит открыть
`node_modules` и прочитать, замерить в живом Chrome, прогнать эталонную фикстуру
через свой модуль. Не «я знаю» и не «в документации написано».

Догадка ошибается не там, где ждёшь, и цена не в самой ошибке, а в том, что
она правдоподобна. Три случая уже стоили времени:

- квота `localStorage` оказалась 5 242 869 символов, но важнее числа было то,
  что `setItem` при переполнении **не затирает старое значение** — то есть
  сломанный канал показал бы автору не «проекта нет», а прошлую версию работы;
- anime.js на неизвестном имени плавности не бросает, а молча ставит линейную:
  дефект, который не виден ни в тесте, ни в консоли;
- поле `border-radius`, сделанное «очевидно» пиксельным, роняло бы панель
  на эталонной фикстуре, где круг задан через `50%`.

Ни одно из трёх не нашлось бы рассуждением. Все три нашлись прогоном.

**Чини корень.** Никогда не глуши ошибку, не подставляй фейковые данные, не пиши
фолбэк-заглушку. Ошибка должна падать громко и в том месте, где возникла.

**Проверяй в браузере.** Открывай собранное приложение, кликай, смотри консоль.
Зелёный юнит-тест ничего не говорит о том, что видит пользователь: в S3 логика
паузы была верна и прошла бы любой юнит-тест, а дефект сидел в звуке.

**Прогоняй `pnpm check`** после каждого изменения. Не «в конце», а после каждого.

**Тест упал — виноват код.** Сначала предполагаем, что сломали продукт, а не
тест. Правка теста ради зелени требует объяснения в коммите. В S3 соблазн
поднять порог детекции увёл бы в продукт щелчок на каждом гейте.

**Не трогай эталонные фикстуры** в `fixtures/projects/`, чтобы починить тест.
Если фикстуру надо обновить — сначала объясни почему.

**Не мерь производительность на занятой машине.** В S6 замер шёл параллельно
с другими задачами: медиана не изменилась, а хвост разошёлся вдвое — испортилась
ровно та величина, ради которой всё затевалось.

**Сравнивать пословно можно только после сопоставления последовательностей.**
Разные инструменты по-разному разбивают текст на слова; сравнение по индексам
даёт правдоподобные числа с видом настоящих.

**Новая зависимость — через ADR.** Короткий, но письменный. С проверкой лицензии
по первоисточнику. GSAP брать нельзя: лицензия запрещает визуальные редакторы
анимации, а инвариант №5 не даёт отделить редактор от плеера.

**Один вертикальный срез за раз.** Доводи до работающего состояния, потом
следующий. Не строй три слоя наполовину.

**Тест, который проверяет вызов обработчика, — не поведенческий тест.**
Четыре e2e нашли дефект наложения: в гейте кликабельная сцена перехватывала
нажатия по кнопкам ответа. Проверка «вызвался ли `answer()`» была бы зелёной,
потому что логика ответа исправна. Тест обязан нажимать по видимой кнопке.

**Координатные пространства не смешивать.** `getBoundingClientRect` и `clientX`
учитывают трансформацию сцены, `offsetLeft` и `clientWidth` — нет. Масштаб
берётся из DOM, никогда из сохранённого значения. Иначе перетаскивание
в редакторе сломается тихо.

## Скиллы и актуальность

**Проверяй свои skills** в начале сессии и перед каждой новой задачей. Если для
задачи есть skill — читай его до того, как писать код, а не после.

**Ищи в интернете.** Твои знания устаревают. Перед выбором библиотеки, версии
или API проверяй текущее состояние поиском. Особенно: версии, лицензии,
живость проекта, изменения браузерных API.

**Датируй находки.** В `docs/research/` каждый файл начинается с даты проверки.

## Когда остановиться и спросить

- Задача требует нарушить инвариант
- Развилка, у которой нет очевидно правильной стороны
- Спайк провалился, и обход неочевиден
- Правка затрагивает схему проекта
- Хочется добавить зависимость, которая тянет много всего
- Что-то в существующем коде выглядит неправильным — не переписывай молча

Остановиться и спросить всегда дешевле, чем откатывать.
