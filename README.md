# Player — интерактивные объяснения в вебе

Внешне похоже на видео: озвучка, таймлайн, анимации. Внутри — DOM,
поэтому зритель может не только смотреть, но и действовать.

Автор ставит на таймлайне **остановки** (гейты) — точки, где плеер
замирает и открывает взаимодействие. Вне остановок кликать нельзя
физически: у сцены выключены указатели, а не «не повешен обработчик».

сегодняшнего дня.

### Одно правило, которое сэкономит вам день

**Документ, который врёт, дороже отсутствующего.** Отсутствующий заставит
пойти и посмотреть, врущий уверенно поведёт не туда. Поэтому здесь принято:
дата в шапке, число со ссылкой `файл:строка`, а всё, чего нет, — в реестре
`debt.md`, а не россыпью по описаниям.

Если найдёте расхождение документа с кодом — это дефект документа, и чинить
его надо там же, где нашли, а не обходить.

## Запуск

Нужен **Node 22+** и **pnpm 10.29.2** (версия закреплена в `package.json`).

```
pnpm install
pnpm exec playwright install chromium   # браузер для e2e, отдельным шагом
cp .env.example .env                    # и вписать ключ, если нужна расшифровка
pnpm dev            # стенд автора  →  http://localhost:5179/
pnpm check          # все проверки разом
```

**Браузер ставится отдельной строкой не по забывчивости.** pnpm 10 не
выполняет постустановочные скрипты, поэтому после `pnpm install` браузера
нет, и `pnpm check` падает на e2e с «browser not found» — по причине
окружения, которую легко списать на продукт. То же самое делает CI
отдельным шагом.

**Ключ Deepgram нужен только для расшифровки** озвучки в слова. Без него
редактор открывается, проект грузится, сцена рисуется и все проверки
проходят; не работает одна кнопка, и падает она громко и по-русски.
Имя без приставки `VITE_` намеренно: ключ читается на стороне
дев-сервера и в браузер не уезжает.

Порт 5179 задан жёстко (`strictPort`), и это не вкусовщина: на общем 5173
живут дев-серверы соседних проектов, а Playwright берёт всё, что отвечает
по адресу, не спрашивая, наше ли оно. Занятый порт обязан падать громко.

### Проверки

```
pnpm check          # типы → юниты → сборка плеера → e2e
pnpm typecheck      # шесть проектов TypeScript
pnpm test:unit      # Vitest
pnpm test:e2e       # Playwright
```

`pnpm check` идёт около 13 минут, из них e2e ≈ 12. Сборка плеера стоит
**перед** e2e не случайно: тесты проверяют, что браузер получает собранный
файл байт в байт.

Два `pnpm check` одновременно дают **ложное красное** — оба поднимают
сервер на 5179 и оба пишут в один `player.js`. Полный прогон только один
за раз.

## Законы, которые нельзя нарушить молча

Их десять, они живут в [`CLAUDE.md`](CLAUDE.md) и охраняются тестами.
Три, о которые спотыкаются чаще всего:

1. **Время даёт только звук.** Ни `setInterval`, ни счётчик кадров не имеют
   права двигать сцену: позиция в аудиоконтексте и есть время проекта.
2. **Один рендер на редактор и плеер.** Редактор импортирует отрисовку из
   плеера. Две реализации — архитектурная ошибка, а не оптимизация.
3. **Схема версионируется.** Любая правка схемы = бамп версии + миграция +
   фикстура + тест. Без исключений, даже для «мелкого поля».

Нарушить закон можно только через новый ADR и прямой ответ владельца.
Если код требует нарушить — остановиться и спросить.

## Как здесь принято работать

Работа идёт **сессиями**. У каждой своя ветка `session-N`, в конце она
вливается в `main`. Ветки прошлых сессий не удалены намеренно: это след
работы, и все они уже в `main`.

У сессии есть задание (`docs/prompts/SESSION-N-PROMPT.md`), журнал находок
(`docs/journal/`) и, если работа крупная, план (`docs/plans/`).
Порядок описан в [`docs/session-protocol.md`](docs/session-protocol.md).

Два правила, купленные дорого:

- **Гипотезу проверяют прогоном, а не уверенностью.** «Я знаю» и
  «в документации написано» не принимаются: квота хранилища, поведение
  движка анимаций и форма поля скругления — три случая, где правдоподобная
  догадка оказалась неверной, и ни один не нашёлся бы рассуждением.
- **Код возврата у конвейера — не код команды.** `pnpm check | tail`
  вернёт код `tail`, а он успешен всегда. Зелень докладывают, увидев числа.

## Лицензии и запреты

**GSAP брать нельзя** — его лицензия запрещает применение в инструментах,
позволяющих создавать анимации визуально, а наш редактор буквально такой.
Взят anime.js под MIT. Бесплатность и разрешённость — разные вещи.

Новая зависимость заводится только через ADR, с проверкой лицензии
по первоисточнику.
