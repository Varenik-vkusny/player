## §3. ОТКАЗ ПРИБОРА: скрытая вкладка не грузит видео

**Найдено 16.08.2026, стоило шести заходов и одного неверного вывода
на подходе.**

Loom не проигрывался: `readyState 0`, `networkState 2` («грузится»)
бесконечно, `MediaError` пуст. Страница с `<video>` вешала рендерер —
`Runtime.evaluate` падал по таймауту 45 с.

**Вывод «у Loom видео вжато в кадр, проверено проигрыванием» был готов
к докладу и был бы неверен.** Спас положительный контроль: обычный
`mov_bbb.mp4` в том же браузере тоже не поехал. То есть отказывал прибор,
а не предмет.

Дальше слои разведены двумя контролями по одному вызову каждый:

| контроль | результат | что исключает |
|---|---|---|
| `canvas.captureStream()` → `<video>` | **играет**, `readyState 4`, 160×90 | элемент, конвейер, композитор целы |
| YouTube (MSE) | **играет**, `readyState 4`, длительность 634.6 с | декодер цел; ломается только ПРОГРЕССИВНЫЙ `<video src=file.mp4>` |
| `fetch` того же mp4 | **206**, `Accept-Ranges: bytes` | сеть цела |
| `canPlayType('avc1.42E01E')` | `"probably"` | кодек поддержан |

**Корень:** `innerWidth × innerHeight` = **0 × 0**, `document.hidden = true`,
`visibilityState = "hidden"`. Окно Chrome свёрнуто либо вкладка не активна
в своём окне. `resize_window` этого НЕ лечит — окно меняет размер, вкладка
остаётся скрытой.

Снимки при этом продолжают получаться, потому что рисуются мимо экрана.
Поэтому отказ читается как факт о сайте.

**Правило на будущее:** когда медиа не едет — спрашивать `innerWidth`
и `document.hidden` ПЕРВЫМ делом, до любых догадок о сайте.

## §5. Спайк S17 — два утверждения, на которых стоит ADR-032

`node spikes/run-bubble-rights.mjs`, отчёт в `spikes/results/s17-bubble-rights.json`.
Прогон 16.08.2026, живой Chromium с окном (не headless: меряется
воспроизведение).

### Замер 1 — указатель одному элементу внутри мёртвой сцены

| капля | `elementFromPoint` капля / сосед / кнопка | щелчки дошли до |
|---|---|---|
| наследует `none` | `body` / `body` / `body` | `body`, `body`, `body` |
| `pointer-events: auto` | **`bubble`** / `body` / **`collapse`** | `bubble, stage` · `body` · `collapse, bubble, stage` |

**Ответ: да, разрешение выдаётся ОДНОМУ элементу, и сосед остаётся мёртвым.**
Кнопка внутри капли достижима — то есть орган управления зрителя можно
положить внутрь самой капли, отдельного слоя не нужно.

**Находка сверх задания: щелчки по капле ВСПЛЫВАЮТ до сцены** (`bubble, stage`),
хотя сцена сама недостижима. `pointer-events: none` отменяет попадание в узел,
но не отменяет всплытие от потомка. У плеера на сцене висит делегированный
обработчик гейта (`player.ts`, `#handleStageClick`) — он эти щелчки УВИДИТ.
Учесть в реализации, а не обнаружить потом.

### Замер 2 — переживает ли звук сворачивание картинки

Фикстура `apps/playground/public/video/talking-head.mp4` проверена отдельно:
2 дорожки, AAC моно 48 кГц, 8 с, средний уровень −26 дБ, пик −6 дБ,
384 000 отсчётов (`ffprobe` + `volumedetect`). Звук настоящий, не тишина.

Прибор: `webkitAudioDecodedByteCount` — счётчик декодированных байт звука.
Ожидание из физики файла: 1.2 с × 4853 бит/с ≈ **728 байт**.

| способ спрятать | Δ времени, с | пауза | Δ байт звука (с отводом / без) |
|---|---|---|---|
| **КОНТРОЛЬ: не прячем** | 1.21 | false | **708 / 832** |
| `display: none` | 1.25 | false | 627 / 631 |
| `visibility: hidden` | 1.20 | false | 600 / 608 |
| `opacity: 0` | 1.24 | false | 685 / 677 |
| `transform: scale(0)` | 1.24 | false | 648 / 656 |
| размер 0 × 0 | 1.23 | false | 1092 / 790 |
| увезли за край окна | 1.24 | false | 648 / 652 |
| **КОНТРОЛЬ: узел вынут из DOM** | **0** | **true** | **0 / 0** |

**Ответ: ни один способ спрятать картинку СТИЛЕМ звук не глушит.**
Глушит ровно одно — вынуть узел из документа.

### Прибор, который соврал, и как это поймано

Первым прибором был `AnalyserNode` через `createMediaElementSource`.
Он показал **RMS 0 во всех строках, включая контроль «ничего не прячем»** —
то есть по нему выходило бы, что звука нет НИКОГДА.

Поймано положительным контролем: строка «не прячем» обязана звучать,
и раз она молчит — молчит прибор.

Гипотеза «отвод сам глушит звук» (`createMediaElementSource` не подслушивает,
а перехватывает выход элемента) проверена вторым прогоном БЕЗ отвода
и **опровергнута**: байты декодируются одинаково в обоих прогонах.

Отдельная грабля первого прогона: дорожка зациклена, и на витке
`currentTime` уходит назад — «размер 0 × 0» показал **Δ = −6.762** на
полностью исправном воспроизведении. Правится приведением к длине файла;
без правки это выглядело бы как дефект ровно одного способа сокрытия.

### Что из этого следует для кода

1. **Сворачивание капли делается стилем, а не удалением узла.** Удаление —
   единственный способ получить тихий дефект из `bubble.md` §4.
2. **Тест на «звук идёт» пишется через прирост
   `webkitAudioDecodedByteCount`**, а не через флаг и не через RMS.
   Прибор нестандартный и живёт только в Chromium — для наших e2e этого
   достаточно, но в коде это надо назвать.
3. **Указатель капле возвращается через `pointer-events: auto` на её узле.**
   Сцена остаётся `none`, сосед остаётся недостижим.
4. **Обработчик гейта на сцене увидит щелчки по капле** и обязан их
   отличать.

## §6. Схема v14 — отрезки «моё»

`Segment.authorSpans: [{ elementId, from: TimeRef, to: TimeRef }]`,
умолчание `[]`. Миграция `migrateV13toV14` тождественна по содержимому.
Фикстура `fixtures/projects/bubble-spans.json` на версии 14, задействует
ОБА вида привязки времени — словом и секундами.

### Что схема сделала невыразимым

- отрезок на несуществующем элементе;
- отрезок нулевой или отрицательной длины;
- перекрытие отрезков ОДНОГО элемента.

Разрешено намеренно: **соприкосновение краёв** (встык) — его порождает
разрез главы; **пересечение отрезков РАЗНЫХ элементов** — у каждого
элемента свой хозяин в свой момент.

### Ошибка, допущенная и пойманная при написании

Первая редакция проверки считала порядок и непересечение ОДНИМ счётчиком
на весь массив. Отрезки разных элементов при этом конфликтовали бы —
то есть проверка запрещала бы законное состояние. Поймано перечитыванием,
до прогона; тест «отрезки РАЗНЫХ элементов пересекаться вправе» заведён
специально под неё и покраснел на сломе «вернуть общий счётчик».

### Тип поймал два места из трёх

`Segment` — обязательное поле, и компилятор указал на все места построения
сегмента: `exits.ts` (новая глава), `split.ts` (ветки развилки), `split.ts`
(продолжение разреза). **Голову разреза он поймать не мог:** она строится
спредом `...segment`, и отрезки протащились бы целиком — молча, без ошибки
типа, оставив у головы хозяина на время, которого у неё больше нет.

Это и есть граница правила «тип сильнее теста»: тип закрыл три случая,
четвёртый закрывается только тестом.

### 23 тестовых литерала Segment

Правились не регексом. Правило «вставить перед `exit:`» проверено
и ОТВЕРГНУТО: в `exits.test.ts` семнадцать строк `exit:` при одной ошибке.
Место брал у компилятора, поле ставил ПЕРВЫМ в литерале — у фабрик в конце
стоит `...overrides`, и вставка после него отняла бы у тестов возможность
задать свои отрезки.

**Грабля собственного инструмента:** регекс разбора ошибок содержал класс
`[a-z0-9/._-]` без заглавных, и все файлы вида `duplicateElements.test.ts`
молча выпадали. Прогон отрапортовал «больше нечего» при четырёх
невыполненных правках. Поймано только тем, что я запустил `tsc` на проекте
тестов отдельно и увидел 6 ошибок вместо 2.

### Доказательство сломом

| слом | покраснело |
|---|---|
| общий счётчик вместо счётчика по элементу | **ровно 1** — «отрезки РАЗНЫХ элементов» |
| убрана проверка существования элемента | **ровно 1** — свой |
| `to <= from` → `to < from` | **ровно 1** — «нулевой длины» |
| убрана проверка перекрытия | **ровно 1** — свой |
| `from < previousEnd` → `from <= previousEnd` | **ровно 1** — «встык законны» |
| умолчание миграции сделано непустым | **ровно 1** — «миграция даёт пустой список» |
| голова не обрезает отрезок (спред тащит целиком) | 4 теста шва, **48 посторонних зелёные** |

Седьмой тест («отрезки доезжают до модели») различающего слома не имеет
и охраняется грубым — «убрать поле из схемы». Названо вслух, а не выдано
за точный.

**Плохо построенный слом, названный отдельно.** Первая попытка убрать поле
целиком уронила проверку в `TypeError` («Cannot read properties of undefined»)
и покрасила семь тестов из семи. Крах красит всё подряд и потому не отличает
специфичный тест от декоративного — слом пришлось строить заново.
