# ADR-001: Язык, рантайм, менеджер пакетов, структура репозитория

Дата: 2026-07-27
Статус: принято

## Контекст

Нужен фундамент, на котором продукт можно писать месяцами без переписываний.
Ограничения заданы инвариантами: плеер собирается **без фреймворка** в
самостоятельный ESM-бандл (№9), направление зависимостей строго
`editor → player → core` (№6), `core` не знает про DOM и React.

Среда разработки: Windows 11, CI планируется на Ubuntu. Это расхождение —
не деталь, оно влияет на скриншотные тесты и переводы строк.

## Варианты

**Node + TypeScript + pnpm workspaces.** Один язык на весь стек, типы выводятся
из схемы, workspaces дают физическую границу между пакетами.
Минус: настройка project references требует внимания.

**Node + TypeScript + npm workspaces.** На одну зависимость меньше. Минус:
медленнее, нет строгой изоляции зависимостей — пакет может импортировать то,
что не объявил, и это всплывёт только при сборке отдельного пакета.

**Deno.** Типы из коробки, ESM родной. Минус: экосистема тестирования и сборки
беднее, Playwright и Vite живут в npm-мире, а нам они нужны обязательно.

## Решение

- **Node 22.19** (проверено на машине), ESM везде, `"type": "module"`.
- **TypeScript в строгом режиме.** `any` только с комментарием, объясняющим причину.
- **pnpm 10.29** с workspaces.
- **Vite** для сборки, **Vitest** для юнитов, **Playwright 1.62** для браузерных
  проверок.
- Структура:

```
packages/core/      типы, схема, чистая логика времени и гейтов. Без DOM и React.
packages/player/    рантайм: рендер сцены в DOM, ведомый таймлайн. Без фреймворка.
packages/editor/    React-приложение. Импортирует рендер из player.
apps/playground/    dev-стенд для ручной проверки
fixtures/projects/  эталонные .json проекты
spikes/             одноразовые эксперименты
docs/adr/, docs/research/, docs/planning.md
```

## Обоснование

Структура принята из ТЗ и подтверждена спайком **S7**: единственная функция
рендера, вызванная из ванильного хоста и из React-хоста, дала **0 различающихся
пикселей из 921 600**. Граница `player ← editor` оказалась не декларацией,
а работающей конструкцией.

pnpm выбран за строгую изоляцию: пакет физически не видит недекларированные
зависимости. Для инварианта №6 это вторая линия обороны после project references.

Playwright 1.62 и его Chrome 151 проверены живыми прогонами S2, S3, S4, S6, S7.

## Последствия

**Направление зависимостей защищается двумя механизмами, не дисциплиной:**
TypeScript project references (обратный импорт не компилируется) и тест
инвариантов, читающий исходники. Один механизм может быть обойдён случайно,
два — уже нет.

**Скриншотные эталоны платформозависимы.** Рендер текста на Windows и Ubuntu
отличается сглаживанием и подстановкой шрифтов. Эталоны хранятся с суффиксом
платформы; **CI сравнивает только linux-эталоны**. Иначе получаем «локально
зелено, на CI красно» и привычку не верить красному.

**Переводы строк зафиксированы до первого коммита** (`.gitattributes`,
`* text=auto eol=lf`), иначе хеши эталонных фикстур поедут между машинами.

**Чего теперь нельзя:** добавлять зависимость в `core`, которая тянет DOM;
импортировать из `player` в `core`; полагаться на глобальные типы браузера
в `core`.
