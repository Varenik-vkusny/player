# ADR-002: Источник времени и движок анимаций

Дата: 2026-07-27
Статус: принято

## Контекст

Инвариант №1: аудио — единственный источник времени. Инвариант №2: таймлайн
ведомый, он создаётся в паузе и никогда не играет сам. Требуется источник
времени, который не расползается за десять минут, и движок анимаций, которому
можно выставлять время извне каждый кадр.

Платформы v1 включают iOS Safari.

## Варианты источника времени

**`<audio>.currentTime`.** Просто, стриминг из коробки, память не расходуется.
**Отвергнут:** в Safari до 27-й версии значение обновляется шагами по 250 мс
(коммит WebKit 311867@main, константа `remoteAudioVideoRendererUpdateInterval`).
Стабильный Safari сейчас 26.5. Это в двенадцать раз больше бюджета на гейт.

**`AudioContext.currentTime` + `decodeAudioData` + `AudioBufferSourceNode`.**
Разрешение до сэмпла, `suspend()` замораживает часы вместе со звуком.
Цена: буфер декодируется целиком, стриминга нет.

**`AudioContext` + `MediaElementAudioSourceNode`.** Стриминг сохраняется, часы
контекстные. Минус: позиция по-прежнему завязана на медиаэлемент, а `suspend()`
и элемент придётся согласовывать вручную.

## Варианты движка анимаций

**GSAP.** Зрелый, точный seek. **Отвергнут по лицензии.** Стандартная лицензия
(редакция 2025-05-30) в разделе I запрещает использование «in tools that allow
users to build visual animations without code», а Competitive Products
определены как ПО, «that enables users to create, edit, or manage animations
through a visual interface». Наш редактор попадает под определение буквально.
Плеер сам по себе разрешён, но инвариант №5 не даёт разделить их. Текста
лицензии нет ни в пакете, ни в репозитории — только на веб-странице, условия
которой правообладатель вправе менять односторонне (раздел VI).

**anime.js 4.5.0, MIT.** Абсолютный seek, точное конечное значение на границе
твина, главный цикл выключается через `engine.useDefaultMainLoop = false`.

**Нативный WAAPI.** Без зависимостей. Минус: нет групповой абстракции —
десятки объектов `Animation` пришлось бы синхронизировать вручную.

## Решение

**Часы:** `AudioContext.currentTime`, дорожка декодируется целиком
(`decodeAudioData`), воспроизводится через `AudioBufferSourceNode`.

**Позиция считается от якоря**, фиксируемого в момент старта источника:

```
audibleCtxTime = ctx.getOutputTimestamp().contextTime      // с проверкой вменяемости
              // запасной вариант: ctx.currentTime - (baseLatency + outputLatency)
position = anchor.mediaTime + (audibleCtxTime - anchor.ctxTime)
position = clamp(position, anchor.mediaTime, duration)
```

**Движок:** anime.js 4.5.0. Таймлайн создаётся с `autoplay: false`, главный цикл
движка выключен, время выставляется каждый кадр: `tl.currentTime = position * 1000`.

## Обоснование

| Утверждение | Измерение |
|---|---|
| контекстные часы не расползаются | **S0b:** наклон расхождения −0.014 мс/мин за 600 с, суммарно 0.14 мс |
| формат исходника не влияет | **S0b:** WAAPI и MP3 дали одинаковый наклон; MP3 не сместился |
| `getOutputTimestamp` в Chrome вменяем | **S1/S2:** проверка на старте вернула `true` |
| движок держит выставленное время точно | **S2:** позиция после остановки 0 мс, недоезд элемента 0 px в 50 прогонах |
| пауза не рвёт звук | **S3:** 0 разрывов сигнала, 0 мс скачка позиции |
| стоимость декода приемлема | **S1/S2:** декод 10 минут — 190–201 мс |

## Последствия

**Дорожка держится в памяти целиком.** Десять минут при 48 кГц заняли
**109.9 МБ** (измерено). Стриминга нет: экран загрузки становится частью
продукта. Дорожка обязана быть **моно** — стерео удвоило бы расход.

**`outputLatency` читается каждый кадр, а не один раз.** Измерено: между двумя
прогонами на одной машине он был 24 мс и 40 мс, а до начала воспроизведения
равен нулю. Прочитав его при инициализации, получишь ноль и будешь всю дорогу
считать позицию неверно. На Bluetooth задержка достигает 178 мс — без
компенсации гейт сработает раньше, чем прозвучит слово.

**Ведомый таймлайн обязан покрывать всю дорожку.** Обнаружено в S1: при
выставлении времени за пределы длительности anime.js прижимает его к концу.
Время таймлайна тихо замрёт, пока аудио идёт, и **ошибки при этом не будет**.
Если анимации кончились на второй минуте, остаток дорожки застынет.

**Чего теперь нельзя:** двигать сцену чем-либо, кроме позиции аудио; включать
главный цикл anime.js; брать GSAP даже в плеер, пока действует инвариант №5.

**Что придётся переделать, если решение неверно:** если `getOutputTimestamp`
окажется сломан на iOS (исторически он там возвращал `contextTime` на порядки
меньше `currentTime`), включится запасная формула — она уже реализована и
логируется громко. Если и она подведёт, придётся вернуться к варианту со
стримингом и мириться с квантованием.

## Не подтверждено измерением

Раздел про iOS написан по документации. Живого iPhone нет; Playwright WebKit
на Windows не воспроизводит ни autoplay-политику iOS, ни поведение
`AudioContext` при блокировке экрана. Отдельно не проверено, обходит ли
`navigator.audioSession.type = "playback"` беззвучный переключатель — в спеке
нормативного подтверждения нет. **Это записанный долг, а не закрытый вопрос.**
