# ADR-013: Граф сегментов — схема v2 и инвариант №4 на границе узлов

Дата: 2026-07-30
Статус: принято

## Контекст

Верхняя сущность схемы была «одна дорожка, одна сцена»:

```
Project { schemaVersion, meta, audio, scene }
```

`docs/planning.md` §5а зафиксировал заранее: ветвления делаются нодами,
и это меняет **не гейт и не плеер, а корень схемы**. Вся дисциплина Сессий
1–3 — провести плеер, предпросмотр и редактор через один `segmentOf` —
существовала ради того, чтобы здесь поменялась одна функция.

Дисциплина себя оправдала: на момент перехода `segmentOf` вызывался ровно
трижды (`player.ts`, `Editor.tsx`, `playground/preview.ts`). Тип `Segment`
не изменился вообще, поэтому рендер, таймлайн и жесты редактора о графе
не узнали.

## Решение: форма схемы

```
Project { schemaVersion: 2, meta, entry: NodeId, nodes: SegmentNode[] }
SegmentNode { id, title, audio { src, duration, words },
                          scene { elements, cues, gates },
                          edges: Edge[] }
Edge { id, to: NodeId, when: When }
When = { kind: 'option', gateId, optionId }
     | { kind: 'correct', gateId }
     | { kind: 'wrong',   gateId }
     | { kind: 'end' }
```

Четыре решения и то, что каждое делает невозможным.

**`audio` и `scene` переезжают внутрь узла без правки полей.** Миграция v1→v2
становится чистой обёрткой, и ни одно поле не может тихо поменять смысл
по дороге. Следствие важнее: `segmentOf(project, nodeId)` возвращает тот же
`Segment`, поэтому инвариант №5 не мог сломаться при переходе — рендер
о графе не знает.

**`meta` остаётся в корне.** Размер сцены — свойство произведения, не узла.
Свой размер у каждого узла добавил бы измерение к инвариантам №5 и №7,
а паритет рендера (S7, 0 различающихся пикселей) измерен для одного размера.

**Рёбра лежат на узле, а не общим списком.** Ребро выбирается только пока
играет этот узел, и удаление узла обязано быть локальной операцией. Общий
список позволил бы ребру пережить удаление узла так, что сам узел об этом
не знает.

**`entry` задан явно.** Порядок в массиве — артефакт редактирования. Сделать
его смыслом значит менять произведение перетаскиванием строки в списке.

**Тип узла назван `SegmentNode`, а не `Node`.** `Node` — глобальный DOM-тип,
и в редакторе он живой: `StageView.tsx` делает `target instanceof Node`.
Импорт одноимённого типа из ядра затенил бы его в том файле, где он нужен.

## Решение: семантика рёбер

**Узел без исходящих рёбер — концовка, а не ошибка.** Объяснение завершается
как и раньше. Именно такой узел производит миграция с версии 1, то есть это
основной случай, а не краевой.

**Правило полного покрытия.** Если у гейта есть хоть одно ребро, его рёбра
обязаны покрывать все исходы этого гейта. Ребра-ловушки нет намеренно:
ловушка — способ не отвечать на вопрос «а что при таком ответе», а схема
обязана заставить автора ответить. Не хочешь ветвить каждый вариант — не вешай
рёбра на этот гейт вовсе, он останется обычным. Так устроены все семь старых
фикстур.

**Одна ось различения на гейт.** `option` и пара `correct`/`wrong` — два
разных способа разделить ответы, и вместе они дают неопределённый приоритет:
вариант может быть одновременно и «вторым», и «неверным».

**Гейт с рёбрами обязан быть проходим.** Бесконечный `retry` запирает все
ветки, кроме верной: неверный ответ не доводит до выхода из гейта, а значит
и до ребра. Это единственное правило, найденное не рассуждением, а попыткой
написать e2e: рёбра были корректны, покрытие полное, а ветка «Нет» —
недостижима навсегда.

Обобщение, которое стоит помнить: **валидность данных не равна достижимости
поведения**. Схема, проверяющая только целостность ссылок, разрешает граф,
который плеер физически не может обойти.

**Ошибка приходит к автору при сохранении, а не к зрителю посреди
объяснения.** Всё перечисленное проверяется при загрузке. В плеере ветка
«рёбра есть, но ни одно не подошло» бросает: доехать до неё нельзя, но тихий
выбор первого попавшегося увёл бы зрителя не туда, и не узнал бы никто.

## Решение: инвариант №4 на границе узлов

Инвариант №4 запрещает перемотку. Пересечение границы перемоткой не является:
одна дорожка кончилась, другая начинается с нуля. По букве инвариант цел.
Но то, что он защищает — отсутствие щелчка и рваного темпа — на стыке под
ударом ровно так же.

**Формулировка: на границе узлов №4 действует как граница на разрыв, а не
как запрет. Стык планируется, а не обнаруживается.**

Обоснование — числа S9 (`docs/research/spikes.md`), а не рассуждение:

| Сценарий | Разрывов | Задержка |
|---|---|---|
| по расписанию, `source.start(when)` | 0 из 3 прогонов | 0, по построению |
| опросом в кадре | **1 на 20 переходов**, в 2 прогонах из 3 | 65.3 мс |

Решающее число — не задержка, а щелчок. 65 мс тишины зритель может
не заметить, щелчок заметит всегда.

Отдельно важно, **почему** опрос столь дорог: задержка это не длина кадра
(она честные 16.7 мс), а унаследованный `outputLatency`. `AudioClock.position`
вычитает задержку вывода намеренно, поэтому любое сравнение `position`
с `duration` наследует её целиком. Величина машинозависимая: в S0b на другой
машине она была 24 и 40 мс. Расписание считается во времени аудиоконтекста,
поэтому машинозависимость из решения уходит вообще.

## Что из этого следует в плеере

**Переходы бывают двух родов, и опасен только один.** Переход по гейту стыком
не является: `freezeAt` уже свёл гейн рампой в ноль и подвесил контекст
(S3: 0 разрывов, 0 мс скачка), поэтому старт следующего узла ничем
не отличается от начала воспроизведения. Живой стык — только у ребра `end`.

**Контекст перед стартом будится явно.** `freezeAt` делает `ctx.suspend()`,
и переход по гейту почти всегда идёт из подвешенного состояния. Забыть —
получить тишину, а не ошибку: источник запустится в остановленный контекст,
и ни один юнит-тест этого не увидит.

**Аудиоконтекст один на плеер, часы свои у каждого узла.** Свой контекст
на узел упёрся бы в лимит браузера, а `destroy()` закрывает его один раз.

**Часы читаются из поля каждый кадр, а не захватываются замыканием цикла.**
На запланированном стыке они подменяются внутри этого же цикла, и захваченная
ссылка дала бы новую сцену на старых часах.

## Отвергнутые варианты

**Рёбра общим списком в корне.** Проще рисовать граф целиком, но плеер
сканировал бы весь список на каждый ответ, а целостность «ребро → живой узел»
перестала бы быть локальной для узла.

**Отдельная сущность `Track`, узел ссылается по `trackId`.** Позволило бы
переиспользовать одну озвучку в разных узлах. Продукт этого не просил,
а незапрошенная гибкость — тот же долг, только замаскированный. Плюс вторая
сущность в первую же миграцию.

**Ребро-ловушка вместо полного покрытия.** Отвергнуто: оно позволяет автору
не ответить на вопрос «а что при таком ответе», и дыра доехала бы до зрителя
вместо автора.

## Следствия

Миграция v1→v2 сворачивает старый проект в граф из одного узла без исходящих
рёбер. Все семь неприкосновенных фикстур открываются, на это есть тест.
Реестр миграций, заведённый пустым в Сессии 1, получил первую запись —
следующие писать по этому образцу.

Инвариант №10 (метки привязаны к словам) становится привязкой **внутри
узла**: у каждого узла свой транскрипт, и разрешить метку чужим значило бы
получить правдоподобные секунды с видом настоящих.

Требуется правка формулировки инварианта №4 в `CLAUDE.md` — она сделана
со ссылкой на этот ADR и **ждёт явного подтверждения владельца продукта**.
