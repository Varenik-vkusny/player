# ADR-021: У дорожки два источника, и оба выражены в схеме

Дата: 2026-08-01
Статус: принято. Схема поднята с v5 до **v6**.
Продолжает [ADR-004](ADR-004-project-format.md) (порядок версионирования)
и [ADR-018](ADR-018-audio-window-and-fork.md) (окно дорожки).

## Контекст

В продукт нельзя было войти со своим материалом. `segment.audio.src` —
строка с путём на сервере, и другого способа адресовать озвучку не
существовало. Автор не мог выбрать свой файл, получить расшифровку
и начать ставить метки по словам на собственном голосе.

Пункты 3 и 32 списка-сторожа висели именно из-за этого; аудио ветвлений
(Сессия 14) без этого не сделать вовсе.

Файл, который автор выбрал в браузере, путём не адресуется. Значит схема
обязана научиться выражать второй источник — иначе выражать его будут
в обход схемы.

## Что отвергнуто

**Класть байты в проект.** Отпадает по замеру: потолок `localStorage` —
5 242 869 символов (S8), а секунда звука это десятки килобайт. Хуже числа
то, что `setItem` при переполнении **не затирает старое значение**: автор
увидел бы не «проекта нет», а прошлую версию своей работы.

**Префикс внутри `src`** (`idb:aud-7f3a…` против `/audio/demo.mp3`).
Соблазнительно тем, что не требует бампа версии: строка осталась строкой.
Отвергнуто ровно поэтому. Схема продолжила бы считать такой проект валидным,
а разбор адреса расползся бы по каждому читателю `audio.src`. Правило,
которое невыразимо, дешевле правила, которое надо проверять.

**Заменить `src` на размеченное объединение `source`** внутри схемы.
Строже всего, но это правка всех 13 эталонных фикстур через миграцию ради
пользы, которой сегодня нет. Отложено: если источников станет три, решение
пересматривается.

## Решение

### 1. В схеме — два необязательных поля и одно правило

```
audio: {
  src?:    string   // файл на сервере
  fileId?: string   // файл, загруженный автором; байты в IndexedDB
  offset, duration, words
}.refine(ровно одно из src и fileId непусто)
```

Эталонные фикстуры не тронуты ни одной: у всех есть `src`, и новое правило
они удовлетворяют без правок.

`migrateV5toV6` данные не переносит и поднимает только номер версии. Это
не признак лишней миграции: в v5 `src` обязателен, значит любой проект v5
уже соответствует новому правилу. Инвариант №7 требует, чтобы миграция
существовала явно, а не подразумевалась.

### 2. У слова появился источник `asr`

`source: 'alignment' | 'tts' | 'asr' | 'manual'`.

Распознавание отделено от выравнивания намеренно. Выравнивание знает текст
заранее и раскладывает по звуку известное; распознавание сначала угадывает
сами слова. Ошибки разной природы: у выравнивания сдвигается граница,
у распознавания **пропадает или подменяется слово**, и якорь `TimeRef`
вида `word` ([ADR-008](ADR-008-timeref.md)) теряет опору целиком.

### 3. Байты — в IndexedDB, в пакете плеера

`packages/player/src/assets.ts`, база `player-assets`, хранилище `audio`,
ключ — сам `fileId`.

Место определено инвариантом №6, а не вкусом. Читать файл обязан тот, кто
заводит звук, то есть плеер; направление `editor → player → core` запрещает
плееру знать про редактор. Ядру место не подходит по другой причине:
`core` не знает про DOM.

Отдельно от `player-preview`: тот перезаписывается на каждом предпросмотре
по единственному ключу `current` — это переменная, а не архив. Озвучка
обязана пережить любое число предпросмотров.

### 4. Превращение источника в адрес — ровно в одном месте

`Segment.src: string` заменён на `Segment.source: AudioSource` —
размеченное объединение. `segmentOf` остаётся той же дверцей, что и был.

Адрес выдаётся `resolveAudioUrl(source)` и потребляется **единственным**
местом во всём плеере — `AudioClocks.clockFor`. Объектный адрес отзывается
сразу после декодирования: дальше живёт `AudioBuffer`, а удержанный
`blob:`-адрес держал бы в памяти ещё и байты файла целиком.

Ключ кэша декодированных дорожек (`url:…` / `file:…`) — строка с префиксом,
то есть ровно то, что отвергнуто для схемы. Противоречия нет: этот ключ
живёт в памяти одного источника часов и не переживает перезагрузку страницы,
а строка в схеме пережила бы сохранение и разъехалась бы по читателям.

## Следствия

**Проект перестал быть переносимым сам по себе.** Файл с `fileId`, открытый
в другом браузере, звука не получит. `resolveAudioUrl` бросает на этом
громко и по-русски — тихо показывать немую сцену недопустимо, она выглядит
как обычный проект без звука.

**Смена озвучки обесценивает `audio.words`, а с ними все метки вида
`word`.** Полная машинерия состояний якоря (`bound` / `orphan` / `pinned`,
`product.md` §4) не делается — это Сессия 14. Сейчас редактор называет
число таких меток и по явному согласию автора переводит их в `seconds`
на их же текущую секунду: картинка на дорожке не сдвигается ни на пиксель,
теряется только связь со словом. Молча не делается ничего.

**Инвариант №9 не задет.** Расшифровка живёт в редакторе и в дев-сервере;
собранный бандл плеера получил только чтение IndexedDB и остался
самостоятельным ESM без внешних импортов.

## Что осталось открытым

- Кто и когда удаляет байты из `player-assets`. Сегодня — никто.
- Один файл, загруженный дважды, займёт место дважды: содержимое
  не хэшируется.
- Ветка без озвучки (`product.md` §2в [Р]) по-прежнему выражается только
  через `src`, потому что `duration` остаётся обязательным положительным.
  → `planning.md` §13.1
