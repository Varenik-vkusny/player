# ADR-012. Какие поля стиля показывает редактор

Дата: 2026-07-29. Статус: принято.

## Контекст

`ElementSchema.style` — свободная карта: `z.record(z.string(), z.union([z.string(), z.number()]))`.
Схема не ограничивает ключи и не будет: перечислять там весь CSS бессмысленно,
а любое ограничение сделало бы невозможным проект, сделанный руками.

Значит набор полей, который редактор **показывает автору**, схемой не задан.
Это продуктовое решение, и без записи оно расползётся: каждый следующий сеанс
работы будет добавлять по полю «раз уж мы здесь», пока панель не превратится
в инспектор CSS.

## Решение

### Правило отбора важнее списка

**Из полей стиля исключается всё, что есть в `ANIMATABLE`.**

Причина не в аккуратности, а в том, что иначе два механизма молча дерутся
за одно свойство. Автор выставит `opacity: 0.5` в стиле, а на элементе висит
анимация появления `opacity 0 → 1` — победит анимация, потому что она пишет
в тот же инлайн-стиль каждый кадр. Автор увидит, что поле «не работает»,
и не поймёт почему: оба значения корректны, оба применены, виден только один.

Поэтому прозрачность и фильтры живут в анимации, положение, размер и поворот —
в геометрии, а в стиле остаётся то, чего не касается ни один из них.

**Второе правило: ни одно поле не двигает раскладку за пределы бокса.**
`padding`, `margin`, `border` в набор не входят. Элемент занимает ровно тот
прямоугольник, который автор видит ручками на сцене; поле, способное это
изменить, сделало бы геометрию в панели враньём.

### Набор

Восемь полей, ключи kebab-case — как в существующих фикстурах:

| Поле | Ключ | Тип значения | Применимо |
|---|---|---|---|
| Шрифт | `font-family` | выбор из списка | текст |
| Кегль | `font-size` | длина, px | текст |
| Насыщенность | `font-weight` | выбор из списка | текст |
| Цвет | `color` | цвет | текст |
| Выравнивание | `text-align` | выбор из списка | текст |
| Межстрочный | `line-height` | число | текст |
| Фон | `background` | цвет | все |
| Скругление | `border-radius` | длина px **или проценты** | все |

Набор описан данными в `packages/editor/src/state/style.ts` (`STYLE_FIELDS`),
а не разметкой панели. Девятое поле должно появляться правкой описания,
без правки компонента — на это есть тест.

### Скругление умеет проценты, и это не исключение из правил

Круг задаётся только через `border-radius: 50%` — другого способа нет.
Круглая фигура (точка, аватар, маркер) — базовая потребность автора, поэтому
поле хранит число вместе с единицей, а не один скаляр. Смешивать их нельзя:
процент считается от размера бокса, пиксель — нет.

Это выяснилось не из рассуждения, а из эталонной фикстуры: у элемента `dot`
в `demo.json` скругление задано процентами, и поле, сделанное «очевидно
пиксельным», роняло бы панель на первом же открытии демо-проекта.

### Значение, которого редактор не понимает, не теряется

`style` — свободная карта, и в ней может лежать что угодно: автор правил JSON
руками, значение пришло из проекта, сделанного другой версией, или это ключ
вне наших восьми. Чтение возвращает размеченное объединение: разобранное
значение либо исходную строку как есть.

Панель показывает такое значение текстом и **не трогает при записи соседних
полей**. Это не мягкость к битым данным: данные не битые, их не умеет
показать наш виджет, и это разные вещи. Ошибка вызывающего кода — запрос
несуществующего поля или запись значения вне закрытого списка — по-прежнему
падает громко.

Разница существенна из-за уже описанной в `status.md` беды: `markSeconds`
бросает прямо в рендере, и вместо одной непонятной метки падает весь редактор.
Падать громко правильно; падать целиком — нет.

## Последствия

**Чего теперь нельзя:**

- добавить в набор поле, пересекающееся с `ANIMATABLE`, — это ловится тестом,
  который перебирает константу, а не глазами ревьюера;
- добавить поле, влияющее на внешний размер элемента;
- захардкодить поле в разметке панели в обход `STYLE_FIELDS`;
- уронить панель на значении, которое редактор не умеет разобрать.

**Что стало можно:** расширять набор правкой одного описания. Расширение —
правка этого ADR, а не молчаливое добавление: список закрыт намеренно, иначе
он перестанет быть решением.

## Что не решено

Набор покрывает текст и простую фигуру. Тени, градиенты, обводка, межбуквенное
расстояние — не входят и появятся, когда появится задача, которая их требует.
Добавлять «на будущее» не будем: незапрошенная гибкость — тот же долг,
только замаскированный.
