# ADR-008: `TimeRef` — размеченное объединение вместо числа

Дата: 2026-07-27
Статус: принято

## Контекст

Инвариант №10: метки времени привязаны к словам транскрипта, а не к
миллисекундам. Секунды — только там, где слова нет.

Смысл инварианта продуктовый. Автор ставит анимацию на слово «энергия». Потом
он правит соседнее предложение или перегенерирует озвучку другим голосом.
Метка обязана остаться на слове «энергия», а не уехать вместе со сдвигом
дорожки. Без этого любая правка текста ломает всю разметку, и продукт
становится непригоден для работы.

Но не всякая метка привязана к слову: заставка в начале, пауза в конце,
элемент, появляющийся «через две секунды после предыдущего» — там слова нет.

## Варианты

**Число секунд.** Просто, привычно. Ломается при любой правке озвучки: все
метки после точки правки уезжают, и починить их можно только руками.

**Только индекс слова.** Переживает правку длительности. Но не переживает
правку **текста**: вставленное предложение сдвигает все последующие индексы,
и метка молча переезжает на другое слово.

**Размеченное объединение: либо секунды, либо ссылка на слово.**

## Решение

```ts
type TimeRef =
  | { kind: 'seconds'; t: number }
  | { kind: 'word'; wordIndex: number; offset: number; anchor: WordAnchor }

type WordAnchor = {
  text: string        // нормализованное слово: строчные, без пунктуации, ё → е
  before: string      // нормализованное предыдущее слово, '' в начале
  after: string       // нормализованное следующее слово, '' в конце
}
```

Разрешение `TimeRef` в секунды — **единственная** функция в `core`, которой
разрешено это делать. Она принимает `TimeRef` и массив слов и падает громко,
если ссылка невалидна.

## Обоснование

**Почему объединение, а не число с необязательным полем.** Размеченное
объединение делает невозможным состояние «указаны и секунды, и слово, и они
противоречат друг другу». Компилятор заставит обработать оба случая в каждом
месте, где время используется. Число с флагом позволило бы забыть проверку,
и ошибка проявилась бы данными, а не типом.

**Почему индекса мало и нужен якорь.** Это не гипотеза, а прямое следствие
измерений S5. Тайминги приходят от внешнего инструмента, и состав слов между
двумя версиями озвучки может отличаться. Якорь позволяет **обнаружить**
расхождение: если слово по индексу не совпадает с `anchor.text`, ссылка битая,
и мы говорим об этом громко, вместо того чтобы тихо анимировать не там.
Соседи `before` и `after` дают возможность найти слово заново, когда индексы
сдвинулись вставкой.

**Почему `offset` отдельным полем.** Автор часто хочет «на полсекунды позже,
чем начнётся слово». Без смещения пришлось бы либо мириться с точностью
до слова, либо переходить на секунды и терять устойчивость.

**Подтверждающее измерение.** S5 показал, что источники таймингов расходятся
систематически: `edge-tts` сообщает начало слова на 43–95 мс раньше реального
звука, Deepgram — на 30–98 мс позже. Числа зависят от инструмента, а слово —
нет. Это и есть довод за то, что хранить надо ссылку на слово, а секунды
вычислять при загрузке из актуальных таймингов.

## Последствия

**Схема хранит ссылку, а не результат.** Секунды никогда не сохраняются
в проекте для меток типа `word` — они вычисляются при загрузке. Иначе после
перегенерации озвучки в файле остались бы устаревшие числа рядом с актуальными
словами, и неясно было бы, кому верить.

**Пустой `words[]` делает `kind: 'word'` невалидным.** Валидация падает при
загрузке, а не в рантайме.

**Появляется операция «перепривязка».** После замены озвучки редактор обязан
пройти по всем `TimeRef` вида `word`, сверить якоря и показать автору те,
что не сошлись. Это работа, которой не было бы при хранении секунд, — цена
устойчивости.

**Чего теперь нельзя:** сравнивать `TimeRef` напрямую как числа; сортировать
метки без разрешения в секунды; кэшировать разрешённое время между загрузками
проекта.

**Что придётся переделать, если решение неверно:** если якорь из трёх слов
окажется недостаточно различающим на длинных дорожках с повторами, придётся
расширять окрестность или добавлять номер предложения. Формат объединения
при этом не меняется — меняется только `WordAnchor`, и это будет миграция
схемы, а не переписывание.
