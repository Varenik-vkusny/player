# ADR-005: Модель гейтов — как устроена остановка и возобновление

Дата: 2026-07-27
Статус: принято

## Контекст

Гейт — центральная механика продукта. Инвариант №3: гейт единственный способ
дать интерактив, вне гейта сцена физически недоступна. Инвариант №4: гейт
останавливает всё сразу, возобновление с той же позиции, перемотки не
происходит никогда.

Бюджеты из ТЗ: перелёт остановки меньше 20 мс, элемент в момент остановки
визуально в финальном состоянии, при паузе и возобновлении нет щелчков.

Осложняющее обстоятельство, выясненное измерением: медиана интервала кадра
на тестовой машине — **18.67 мс**. Один кадр съедает почти весь бюджет.
Модель, которая тормозит «на ближайшем кадре после гейта», в 20 мс не уложится
ни при какой аккуратности.

## Варианты

**Тормозить на кадре, когда заметили пересечение.** Просто. Перелёт равен
задержке обнаружения, то есть длине кадра. Финальное состояние анимации —
«где успели», то есть чуть-чуть недоехавшее.

**Планировать остановку заранее по расписанию Web Audio.** Точно до сэмпла.
Но `AudioContext.suspend()` не принимает момент времени (в отличие от
`OfflineAudioContext`), поэтому точно запланировать саму остановку нельзя.

**Разделить логическое время и физическую остановку.** Логическая позиция
**записывается** равной времени гейта, а физически звук глушится рампой,
запланированной по расписанию, и контекст засыпает несколькими миллисекундами
позже, когда слышать уже нечего.

## Решение

Третий вариант.

```
freezeAt(t):
  запланировать рампу гейна в ноль, заканчивающуюся ровно в момент t
  заморозить логическую позицию: position := t
  остановить источник на конце рампы
  ctx.suspend()

resumeFromFreeze():
  ctx.resume()
  start(offset = t)            // новый источник, новый якорь
  рампа гейна из нуля в единицу за 8 мс
```

Блокировка взаимодействия: сцена вне гейта получает `pointer-events: none`.
Обработчики при этом **не снимаются никогда** — недоступность обеспечивает
браузер, а не наша аккуратность.

## Обоснование

| Утверждение | Измерение (S2, 50 прогонов) |
|---|---|
| перелёт обнаружения ограничен кадром | медиана 17.23 мс, p95 18.45, максимум **18.57 мс** |
| логическое время встаёт точно на гейте | **0 мс** |
| элемент ровно в финальном состоянии | недоезд **0 px**, 0 прогонов с отклонением > 0.5 px |

| Утверждение | Измерение (S3, 20 циклов) |
|---|---|
| нет щелчков | **0** разрывов внутри непрерывных участков записи |
| нарастание работает | громкость первого сэмпла после паузы **0** |
| возобновление без перемотки | скачок позиции **0 мс** |

| Утверждение | Измерение (S4) |
|---|---|
| вне гейта элемент недоступен физически | `elementFromPoint` возвращает `body`, кликов прошло **0 из 6** |
| в гейте всё работает | кликов прошло **6 из 6** |

Ноль пикселей недоезда — следствие того, что время выставляется точно на конец
твина, а anime.js на границе пишет авторское конечное значение, а не результат
интерполяции.

## Последствия

**Рампа гейна обязана быть симметричной.** Это не эстетика. В первом прогоне S3
затухание было сделано, а нарастание забыто — выход прыгал от тишины сразу
к текущей амплитуде волны, что дало 15 щелчков на 20 циклов. Щелчок был бы
слышен при **каждом** гейте, то есть в самом частом действии продукта.

**Первые 8 мс после возобновления звучат с нарастанием.** Осознанная цена
за отсутствие щелчка.

**Перемотки не существует конструктивно, а не по договорённости.** Возобновление
всегда стартует с той же цифры, которая была записана при остановке.

**Перелёт 18.57 мс укладывается в бюджет 20 мс с запасом полтора миллисекунды.**
Полагаться на этот запас нельзя: на машине с более длинным кадром обнаружение
будет позже. Но на **логическую** позицию это не влияет — она задаётся явно.
Если бюджет когда-нибудь окажется нарушен, пострадает только момент реакции
интерфейса, а не синхронность звука и картинки.

**Чего теперь нельзя:** снимать обработчики вместо `pointer-events`; тормозить
без рампы; возобновлять с позиции, отличной от записанной; ставить гейт
позже конца дорожки.

**Что придётся переделать, если решение неверно:** если окажется, что рампа
в 8 мс слышна как «проглоченный слог», её длину придётся уменьшать, а щелчок
подавлять иначе — например, поиском ближайшего перехода сигнала через ноль.
