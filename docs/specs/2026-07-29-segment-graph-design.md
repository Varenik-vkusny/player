# Сессия 4, заход 1: объяснение становится графом

Дата: 2026-07-29. Статус: на согласовании.

## Цель

Ответ на гейте выбирает, что зритель услышит дальше.

Проверяемо это означает: в редакторе собрать объяснение из двух узлов
с развилкой, сохранить, открыть в плеере — и увидеть, что один вариант ответа
ведёт в одну сцену со своей озвучкой, другой в другую. Плюс: все семь старых
фикстур открываются после миграции, а стык узлов измерен, а не обещан.

## Что именно ломается

Верхняя сущность схемы сегодня — «одна дорожка, одна сцена»:

```
Project { schemaVersion, meta, audio, scene }
```

`planning.md` §5а зафиксировал заранее: ноды меняют **не гейт и не плеер,
а корень схемы**. Вся дисциплина Сессий 1–3 — провести плеер, предпросмотр
и редактор через один `segmentOf` — существовала ради того, чтобы здесь
поменялась одна функция.

Разведка это подтвердила: `segmentOf` вызывается ровно трижды —
`packages/player/src/player.ts:80`, `packages/editor/src/Editor.tsx:82`,
`apps/playground/src/preview.ts:47`. Дверца цела.

## Схема v2

```
Project { schemaVersion: 2, meta, entry: NodeId, nodes: Node[] }
Node    { id, title, audio { src, duration, words },
                     scene { elements, cues, gates },
                     edges: Edge[] }
Edge    { id, to: NodeId, when: When }
When    = { kind: 'option', gateId, optionId }
        | { kind: 'correct', gateId }
        | { kind: 'wrong',   gateId }
        | { kind: 'end' }
```

Четыре решения и то, что каждое делает невозможным.

**`audio` и `scene` переезжают внутрь узла без единой правки полей.** Значит
миграция v1→v2 — чистая обёртка, и ни одно поле не может тихо поменять смысл
по дороге. Следствие важнее: `segmentOf(project, nodeId)` возвращает **тот же
самый `Segment`**, что и сегодня, поэтому `Player`, `ScenePreview` и `StageView`
не меняются вообще. Инвариант №5 не может сломаться при переходе на граф,
потому что рендер не узнаёт о нём.

**`meta` остаётся в корне.** Размер сцены — свойство произведения, не узла.
Свой размер сцены у каждого узла добавил бы измерение к инвариантам №5 и №7
без продуктовой причины, а масштабирование уже измерено (S7, паритет 0 пикселей)
именно для одного размера.

**Рёбра лежат на узле.** Ребро выбирается только пока играет этот узел, и плееру
на каждом ответе нужны «рёбра, выходящие отсюда». Общий список заставил бы
сканировать всё на каждый ответ и позволил бы ребру пережить удаление узла так,
что сам узел об этом не знает. При рёбрах на узле удаление узла — локальная
операция, а целостность «ребро → живой узел» проверяется одним проходом.

**`entry` задан явно.** Порядок в массиве — артефакт редактирования. Сделать его
смыслом значит менять произведение перетаскиванием строки в списке.

## Миграция v1 → v2

Реестр `MIGRATIONS` заведён с Сессии 1 и до сих пор пуст. Первая запись должна
стать образцом для следующих десяти.

```
1 → 2:  { schemaVersion, meta, audio, scene }
     ↦  { schemaVersion: 2, meta, entry: 'node-1',
          nodes: [{ id: 'node-1', title: meta.title,
                    audio, scene, edges: [] }] }
```

Чистая функция, `audio` и `scene` переносятся по ссылке. Старый проект
становится графом из одного узла без исходящих рёбер — то есть объяснением
с одной концовкой, что и есть его сегодняшнее поведение.

Фикстур **семь**, а не пять, как сказано в брифе: `minimal`, `two-gates`,
`edge-cases`, `demo`, `e2e`, `empty`, `scene-gate`. Все семь неприкосновенны
и все семь обязаны открываться. Плюс новая фикстура `branching.json` —
два узла и развилка, эталон для e2e.

## Семантика рёбер

### Узел без исходящих рёбер

Это концовка, а не ошибка. Объяснение завершается ровно как сегодня:
`player.ts` доходит до `#finish()`, состояние `'ended'`. Именно такой узел
производит миграция из v1, то есть это основной случай, а не краевой. Покрывается
отдельным тестом, чтобы не выродиться в случайность.

### Ответ не подошёл ни под одно ребро

Заглушки не будет — `CLAUDE.md` запрещает глушить ошибку и подставлять фолбэк.
Случая два, и они разного рода.

**У гейта вообще нет рёбер.** Это не развилка, а обычный гейт. Ответ
обрабатывается сегодняшней логикой `onWrong` и `maxAttempts`, воспроизведение
продолжается внутри узла. Законно и часто — так работают все семь старых фикстур.

**У гейта есть рёбра, но ни одно не подошло.** Автор сделал развилку и забыл
случай. Ловим это **при загрузке, а не при показе**, правилом полного покрытия
(ниже). Тогда при проигрывании случай недостижим; если он всё-таки настанет —
падаем громко в том месте, где возник.

Смысл решения: ошибка приходит к автору в момент сохранения, а не к зрителю
посреди объяснения.

### Правило полного покрытия

**Если у гейта есть хоть одно ребро, его рёбра обязаны покрывать все исходы
этого гейта.** Ребра-ловушки нет и не будет: ловушка — это способ не отвечать
на вопрос «а что при таком ответе», а схема обязана заставить автора ответить.

Не хочешь ветвить каждый вариант — не вешай рёбра на этот гейт вовсе. Он
останется обычным гейтом, и воспроизведение продолжится внутри узла. Это
законный и самый частый случай: так устроены все семь старых фикстур.

| Вид гейта | Допустимые наборы рёбер |
|---|---|
| `choice` | пусто · по одному `option` на **каждый** вариант · `correct` **и** `wrong` вместе |
| `input` | пусто · `correct` **и** `wrong` вместе |
| `continue` | только пусто — у него один исход, ветвить нечего |

**Смешивать `option` и `correct`/`wrong` на одном гейте нельзя.** Это две разные
оси различения, и вместе они дают неопределённый приоритет: вариант может быть
одновременно и «вторым», и «неверным».

`end` — ось третья и с гейтами не конфликтует: оно срабатывает не по ответу,
а по тому, что узел доиграл. На узел допускается **не более одного** `end`,
иначе выбор следующего узла неоднозначен.

## Инвариант №4 на границе узлов

№4 запрещает перемотку. Пересечение границы перемоткой не является: одна дорожка
кончилась, следующая начинается с нуля. По букве инвариант цел. Но то, что он
защищает — отсутствие щелчка и рваного темпа — на стыке под ударом ровно так же.

**Формулировка, которую закрепляет ADR-013: на стыке №4 действует как граница
на разрыв, а не как запрет.** Остановка на гейте уже измерена (S2: перелёт
18.57 мс, логическая позиция 0 мс), пауза измерена (S3: 0 разрывов, 0 мс скачка).
Стык обязан удержаться в сопоставимых числах.

### Спайк S9

Повторяет методику S2 и S3 на границе сегментов. Три числа:

1. **Разрывов звука на стыке** — детекция как в S3, где получилось 0.
2. **Задержка стыка** — от конца дорожки A до первого слышимого сэмпла B, мс.
3. **То же при недекодированном следующем узле** — число, которое обосновывает
   политику предзагрузки, а не наоборот.

Гнать на незанятой машине. В S6 фон не тронул медиану и развалил хвост вдвое,
а задержка стыка — величина хвостовая.

Замечание к источнику: `planning.md:213` говорит «измерение **вроде S3**,
но на границе сегментов». Номер S9 введён брифом сессии, в планировании его нет.

## Когда декодируется следующая дорожка

**Триггер — открытие гейта, а не конец узла.** На гейте время стоит, зритель
думает: это единственное гарантированное окно простоя во всём произведении.
И ровно там уже известен список кандидатов — исходящие рёбра узла. Декодируем
цели всех (обычно две-четыре), а не одну.

Для узла без гейта (сквозное ребро `end`) триггер — за N секунд до конца дорожки,
где N берётся из числа S9 плюс запас.

Две страховки:

- **Декодирование не трогает часы.** Сегодня `AudioClock` владеет одним буфером
  (`clock.ts:69`). Новый буфер оседает в отдельном кэше по `src`, а часам
  отдаётся уже готовым. Инвариант №1 остаётся: источник времени один.
- **У кэша нужен потолок.** Комментарий `clock.ts:24-29` честно пишет «стриминга
  нет осознанно… цена — память». С N узлами эта цена умножается, и бюджет надо
  назвать числом, а не намерением.

Отдельно: конец дорожки сегодня ловится **опросом** — `player.ts:268`,
`position >= clock.duration - 0.02`. На стыке этот опрос будет решать момент
переключения источника, при том что `CLAUDE.md` записал ловушку «готовность
сообщается событием, а не опросом». S9 должен показать, достаточно ли опроса
в кадре, или переключение надо планировать заранее по времени контекста.

## Дверца

`segmentOf(project)` → `segmentOf(project, nodeId)`, плюс `entryNodeOf(project)`.
Тип `Segment` не меняется. Три места вызова правятся, всё остальное — нет.

Разведка нашла две настоящие утечки мимо дверцы:
`apps/playground/src/main.ts` читает `project.audio.duration`,
`project.audio.words` и `project.scene.gates` напрямую. Это чинится в срезе 2.

Обращения из `packages/core/src/schema.ts` утечкой не являются: валидатор
определяет формат, ему читать эти поля положено. Обращения из редьюсера
`packages/editor/src/state/project.ts` — сторона записи, парная к `segmentOf`,
и ADR-010 её оговаривает.

**Чего не хватает: охранного теста.** Список импортов редактора закрыт
и охраняется (`invariants.test.ts:82`), а правило `segmentOf` защищено только
комментариями. Дисциплина, ради которой затевалась вся сессия, охраняется хуже,
чем список зависимостей. Срез 2 добавляет тест.

## Граф в редакторе

По ADR-010 правила живут вне компонентов. Новый чистый модуль
`packages/editor/src/state/graph.ts`: создать узел, соединить рёбра, удалить узел
с его входящими рёбрами, проверить достижимость от `entry`, найти непокрытые
варианты гейта. Юнит-тесты на модуль, вид — минимальный.

Вид редактора будет переписан целиком в отдельной сессии, поэтому здесь
интерфейс становится функциональнее, а не красивее.

Три места смены: `Editor.tsx:82` (дверца), `state/project.ts` (редьюсер),
`state/editorHistory.ts` (история). Остальной редактор спрашивает `segment`,
а не `project`, и перехода на граф не заметит.

Ловушка, которая станет острее: свежий `ScenePreview` стоит на нуле, а смена
узла — структурная правка по определению. После каждого переключения узла время
надо выставлять заново.

## Что проверяется тестами

- Все семь старых фикстур мигрируют и загружаются; миграция — чистая функция
- Проект версии 3 не открывается (инвариант №7 уже это проверяет, расширить)
- Узел без исходящих рёбер завершает объяснение, а не падает
- Гейт с `option`-ребром и непокрытым вариантом не проходит валидацию
- Ребро на несуществующий узел не проходит валидацию
- e2e на `branching.json`: **нажатие по видимой кнопке** одного варианта приводит
  в один узел, другого — в другой, и это видно на экране
- Скриншотный паритет редактора и плеера не изменился
- Список импортов редактора не вырос
- Новое: `segmentOf` — единственный путь к `audio` и `scene` вне ядра и редьюсера

## Границы захода 1

Срезы 1–5: схема, дверца, спайк S9, переход в плеере, граф в редакторе.

Библиотека фигур, заготовки анимаций и шаблоны сцен — заход 2, отдельный показ.
Решение владельца продукта: один связный кусок за раз.

Не делается вовсе: бэкенд, загрузка своего аудио, резка дорожки, совместное
редактирование, экспорт, переписывание внешнего вида.

## Открытые вопросы

**Документация разошлась с измерениями.** `CLAUDE.md` в таблице подтверждённого
пишет «квота `localStorage` под проект», а `spikes.md:611` фиксирует, что канал
предпросмотра **переведён на IndexedDB** по итогам того же замера. Измерение
верное, вывод в закон не перенесён. Читающий только `CLAUDE.md` будет уверен
в неверном канале. Правку закона не делаю без ответа владельца.

**`status.md` отстал на коммит.** В «не сделано» значится «S8 не в spikes.md»,
а S8 лежит в `spikes.md:608`.

**Бриф говорит про пять старых фикстур, их семь.** Мигрируются и покрываются
тестом все семь.

## Решения, которые станут ADR

- **ADR-013** — граф сегментов: форма схемы v2, семантика рёбер, поведение
  при узле без исходящих рёбер и при непокрытом ответе, смысл инварианта №4
  на стыке.
- **ADR-014** — политика декодирования следующего узла, по числам S9.
