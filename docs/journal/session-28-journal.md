## 2. ПРИЁМКА ГЛАЗАМИ ЗАРАБОТАЛА. Долг §6о Сессии 27 закрыт

Это главная находка сессии, и она отменяет вывод предыдущей.

### 2а. Прошлый диагноз опирался на замер, которого не было

Журнал С27 §6о закрыл сетевую версию таблицей, где строка
«стенд слушает» = `0.0.0.0`.

**Стенд не слушал `0.0.0.0`.** `pnpm dev` печатает прямым текстом:

```
➜  Local:   http://localhost:5179/
➜  Network: use --host to expose
```

В `apps/playground/vite.config.ts` заданы `port: 5179` и
`strictPort: true`, а `host` не задан вовсе — значит привязка к
localhost, по умолчанию Vite. `curl` на сетевые адреса машины давал
`000` (соединения нет), и это сходилось бы с любой гипотезой.

То есть верная гипотеза («браузер на другой машине, нужен маршрут»)
была отвергнута доказательством, которое само было неверным.

### 2б. Ступенчатая проверка вместо перебора

Ошибка §6о была в переборе адресов без контрольного вопроса. Здесь
порядок обратный — от общего к частному, каждая ступень отделяет класс
причин:

| ступень | замер | что отсекает |
|---|---|---|
| `example.com` в браузере расширения | **открылся, подтверждён снимком** | расширение и разрешения исправны |
| `netstat` после `vite --host 0.0.0.0` | `0.0.0.0:5179 LISTENING` | привязка |
| `curl` на сетевые адреса машины | **200** | стенд открыт наружу по-настоящему |
| те же адреса из браузера расширения | **обе навигации откатились** | маршрута из той сети нет |
| публичный туннель `ngrok` | **редактор открылся** | причина была именно в маршруте |

### 2в. Как поднимается, дословно

```
ngrok http 5179 --host-header=rewrite --log=stdout --log-format=logfmt
```

затем адрес берётся из `http://127.0.0.1:4040/api/tunnels`, поле
`public_url`. Стенд поднимается обычным `pnpm dev` — открывать его
наружу не нужно, туннель подключается с той же машины.

Три вещи, каждая из которых стоила отдельной попытки:

- **`--host-header=rewrite` обязателен.** Без него Vite видит чужой
  Host и отбивает запрос проверкой хостов. Флаг подменяет заголовок на
  `localhost:5179`, и **`vite.config.ts` трогать не приходится вовсе** —
  отладочная оснастка не залезает в конфиг проекта;
- **адрес меняется при каждом запуске** (`ce6a-…` → `f126-…`). Записывать
  его в документацию нельзя, брать только из API;
- **бесплатный ngrok показывает заглушку** «You are about to visit…»
  с кнопкой «Visit Site», один раз на браузер. Обойти можно заголовком
  `ngrok-skip-browser-warning`, но из браузера заголовок не выставить,
  поэтому кнопку жмём.

### 2г. `pnpm dev -- --host` НЕ РАБОТАЕТ, и выглядит это как «не помогло»

`pnpm` передаёт `--` литералом. Vite получает `vite "--" "--host" "0.0.0.0"`,
разбирает как позиционные аргументы и молча игнорирует. В выводе
остаётся та же строка `Network: use --host to expose` — то есть флаг
как будто применён и не подействовал, хотя он не дошёл.

Рабочая форма: `pnpm exec vite --host 0.0.0.0` из `apps/playground`.

Родня грабле про `cmd | tail`: оболочка отдаёт правдоподобный результат
не той команды.

## 3. ПРИБОР СОВРАЛ ДВАЖДЫ, ПО-РАЗНОМУ

Оба случая — про одно: доклад инструмента о действии не является
доказательством действия.

**`navigate` доложил успех для страницы, которая не открылась.** Вернул
`Navigated to http://26.52.186.58:5179/` и даже заголовок вкладки
`26.52.186.58`. Снимок показал **example.com** — вкладка откатилась.
Если бы я поверил докладу, вывод был бы «локальная сеть работает».

**`read_page` показал полный редактор на ЧЁРНОМ экране.** Дерево отдало
всё: каталог элементов, шаблоны, список элементов, слайды, дорожку.
Снимок при этом был сплошь чёрный. Ловушка в умолчании инструмента:
`filter` по умолчанию `all`, то есть **включая невидимые элементы**.
«Есть в дереве» не значит «зритель видит» — ровно то же, что
`style.display = ''` в `CLAUDE.md`.

Развязку дал не спор двух приборов, а третий замер — геометрия:

```
.ed-root  1470×835  display: grid  visibility: visible  opacity: 1
elementFromPoint(центр) → .ed-slide-strip-head
```

Раскладка настоящая, значит чернота — артефакт снимка, а не состояние
страницы. После `scroll_to` снимок отдал редактор целиком.

**Вывод для будущих сессий:** при расхождении снимка и дерева спрашивать
геометрию (`getBoundingClientRect`, `elementFromPoint`), а не выбирать,
какому из двух приборов верить.

## 5. Развилка по группам закрыта владельцем

**Решение 08.08.2026: координаты детей — ОТ ГРУППЫ.** Группа —
полноценный элемент со своим состоянием, как у Canva (реестр отличий,
строка 8).

Развилка выносилась с измеренной ценой, а не на глаз:

- `.x` читается в **37 местах, 12 файлов**;
- `renderScene` строит **плоский** DOM (`render.ts:176-183`), порядок
  наложения делает `zIndex` (`:120`);
- значит выбор «от группы» обязывает сделать рендер рекурсивным — это
  правка ЕДИНСТВЕННОГО рендера, охраняемого инвариантом №5;
- вложенность и `transform` связаны жёстко: повёрнутый узел-группа
  создаёт containing block, и `position: absolute` детей начинает
  считаться от группы. Относительные координаты и вложенный DOM — не два
  решения, а одно.

**Следствие для объёма, названное вслух:** Задача 1 перестаёт быть
дешёвой. Оценка промпта (150–250 k, «по образцу v10») относилась к
варианту «от сцены» и к выбранному варианту неприменима.

## 6. МИНА, НАЙДЕННАЯ ГРЕПОМ ДО КОДА: `flipX` снимался бы морфингом

`morph.ts`, ветка `morph`:

```
scaleX: [scaleFactor(from.width, to.width), 1],
scaleY: [scaleFactor(from.height, to.height), 1],
```

Движок анимирует `scaleX` **в единицу**. Значит «очевидная» реализация
отражения через `transform: scaleX(-1)` умирала бы на первом же переходе:
элемент доехал бы до следующего слайда неотражённым.

**Почему это опасный класс.** В модели остаётся `flipX: true`, поэтому
юнит-тест на состояние зелёный, схема цела, разбор проходит. Расходится
только увиденное — а увидеть было нельзя две сессии подряд (§2).

Стоило одного грепа по `morph.ts`. Отсюда решение: в этом заходе поля
отражения заводятся ТОЛЬКО в схеме, движок их не применяет, и причина
записана прямо у поля, а не в чьей-то голове.

## 8. ПРОЕКТ СНОВА ЗАЩИЩЁН ЛУЧШЕ, ЧЕМ Я ПРЕДПОЛАГАЛ

После правок юнитов стало на один больше, чем объяснялось моими
изменениями. Число, которое нечем объяснить, — повод не докладывать,
а искать.

Гипотезы («тест на миграцию», «параметризация каталогом») проверялись
и отпадали. Ответ дал не разбор, а **сравнение имён тестов на двух
деревьях**: разошёлся ровно один файл, `renderers.test.ts`, 6 → 7.

Слом подтвердил: убрать `registerElementRenderer('group', …)` — краснеет
ровно один тест, «у типа „group" из схемы есть зарегистрированный
рендерер», и ни один сосед.

**Свой тест на это писать было бы дубликатом** — тот самый случай,
из-за которого в С27 удалили три теста из десяти.

## 9. ТРИ ГРАБЛИ СЛОМА, КАЖДАЯ СВОЯ

Доказательство сломом само оказалось источником трёх ошибок.

### 9а. Репортёра `basic` в vitest 4 НЕТ, и молчание выглядело находкой

Скрипт-ломатель звал `vitest run --reporter=basic`. В vitest 4 такого
репортёра нет: запуск падает на старте с `Failed to load custom Reporter
from basic`. Разбор вывода не находил ничего и печатал по всем четырём
запретам:

```
!! НИ ОДИН ТЕСТ НЕ ПОКРАСНЕЛ — проверка декоративна
```

То есть несостоявшийся замер выглядел как катастрофическая находка —
родня грабле С27 «слом, который не компилируется, — не слом».

**Спасла контрольная строка.** Рядом стояло «итог не найден»: разбор
не нашёл даже сводки `Tests …`. Без неё вывод был бы правдоподобен
и полностью ложен.

Правило: у разбора чужого вывода обязана быть строка, которая
отличает «замер прошёл и дал ноль» от «замер не прошёл».

### 9б. Слом проверки цикла НЕ КРАСНЕЕТ — он вешает прогон

При снятой проверке подъём до корня по данным `g → h → g` не кончается
никогда: `current` вечно чередуется между двумя группами. Процесс намотал
**351 секунду** процессорного времени, прогон не завершился, скрипт был
убит по времени.

Это доказывает, что проверка несущая, сильнее любого красного. Но и
объясняет, почему первый скрипт «завис»: он не был медленным, он крутил
бесконечный цикл.

Собственный `superRefine` от этого защищён по построению: `seen`
пополняется новым идентификатором каждый оборот, а их конечное число.

### 9в. УБИТЫЙ СКРИПТ ОСТАВЛЯЕТ ПРОДУКТ СЛОМАННЫМ

Скрипт восстанавливал схему **в конце**, после всех четырёх сломов.
Убитый на третьем, он оставил в `packages/core/src/schema.ts` выключенную
проверку цикла — и уехал бы в коммит незамеченным, потому что все
остальные тесты при этом зелёные.

Вторая попытка ставила `trap … EXIT`, и та тоже не сработала: резервная
копия ушла в `$TMPDIR`, а восстановление читало другой путь.

**Что сработало:** контрольный коммит ПЕРЕД сломом, и восстановление
через `git checkout -- <файл>`. Единственный способ, не зависящий
от аккуратности самого скрипта.

Проверять после каждого слома не «зелено ли», а **грепом — убран ли
слом**. Зелень тут ничего не значит: выключенная проверка зелёная
по определению.

## 11. Множественное выделение: что решено и чем доказано

Первый кусок, после которого в редакторе появилось видимое новое.

**Модель:** поле «что выделено» заменено СПИСКОМ (`selectedIds`), плюс
один узкий доступ `soleSelectedId` для мест, которым нужно «ровно один»
(инспектор, ручки). Второе поле рядом с одиночным выделением пришлось бы
согласовывать в каждом действии редьюсера — та же ошибка, что чинили
у перечня типов элемента.

**Удаление сделано пачкой сразу**, а не оставлено на потом: кнопка
«Удалить», не работающая при трёх выделенных, — ровно тот наполовину
сделанный срез, от которого предостерегает `CLAUDE.md`. Один вызов —
один шаг истории, и `Ctrl+Z` возвращает всех разом.

**Стрелки клавиатуры двигают пачку** одним шагом отмены: каждый элемент
правится с `commit: false`, и в конце один `commit`. Без этого отмена
разъезжала бы пачку по одному.

### 11а. Клик по пачке требует ДВУХ противоположных решений

Нажатие по уже выделенному элементу пачку **сохраняет** — иначе её
нельзя потянуть, поехал бы один элемент. Отпускание **без движения** её
схлопывает — иначе уменьшить выделение можно было бы только щелчком
по пустому месту.

Обе половины нужны, и вторую я сначала не сделал. Нашёл её не
рассуждением: e2e «обычный клик схлопывает выделение» покраснел, и это
был тот случай, когда виноват код, а не тест.

### 11б. У общей рамки нет своего угла, и считать её надо ПО УГЛАМ

`unionBox` строит охватывающий прямоугольник по четырём повёрнутым углам
каждого бокса, а не по его `x/y/width/height`. Квадрат 100×100 под 45°
занимает 141.42, а не 100 — «очевидная» формула обрезала бы элемент,
причём ТОЛЬКО на повёрнутых, то есть выглядела бы как редкий глюк.

`rotation` общей рамки всегда 0: у двух элементов, повёрнутых по-разному,
общего наклона нет, а взять чей-то один значило бы соврать про остальных.
Отсюда же решение не рисовать ручки при нескольких выделенных: ручка
без действия за ней хуже отсутствующей — автор потянет и решит,
что редактор сломан.

### 11в. ЛИШНИЙ КЛЮЧ В ОПЦИЯХ PLAYWRIGHT ВЫБРАСЫВАЕТСЯ МОЛЧА

Первый прогон нового e2e дал 4 падения из 6, и я чуть не пошёл искать
дефект в продукте. Причина была в тесте: я написал

```
page.mouse.click(x, y, { modifiers: ['Shift'] })
```

а у `mouse.click` полей модификаторов НЕТ вовсе — только `button`,
`clickCount`, `delay` (проверено по `types.d.ts` в `node_modules`,
не по памяти). Лишний ключ принят и отброшен: тест выглядел как проверка
Shift, а кликал без него.

Тот же класс, что anime.js с неизвестным именем плавности. Рабочая
форма — зажать Shift клавиатурой вокруг клика.

**Ни библиотек, ни ADR этот кусок не потребовал.** `react-selecto`
