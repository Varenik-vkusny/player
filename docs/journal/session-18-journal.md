Находки пишутся В МОМЕНТ НАХОДКИ. Память о находках гниёт быстрее чисел:
половина списка «не закрыто» в Сессии 15 существовала минуты и без журнала

## До кода

1. **`session-17` влита в `main`.** Промпт обещать этого не мог и правильно

2. **Числа промпта сошлись с измеренными.** `pnpm check` один прогон,
   exit 0, 4.9 мин: 36 файлов юнитов, 1232 юнита, e2e 238 прошло,

   разошлось с измеренным и прожило целую сессию.* Контроллер.

3. **Опасение §14.13 «между соседями может не быть свободного слова» —
   ЛОЖНОЕ.** Зонд на `demo.json` через `ProjectSchema`:
   `ЗОНД А: ПРИНЯТО` — две метки на ОДНОМ слове со смещениями 0 и +0.05 с;
   `ЗОНД Б` — отвергнуто «два слайда на одной секунде (0.100)».
   *`TimeRef` вида `word` хранит слово ПЛЮС смещение, а схема
   (`schema.ts:632`) сравнивает разрешённые СЕКУНДЫ. Ограничение — свободный
   момент, а не свободное слово, и оно на два порядка мягче.* Контроллер,
   временным юнит-тестом (удалён после ответа).

4. **Сирота при переносе в чужую часть — неверный ответ, хотя промпт его
   предлагал.** *`orphan` по ADR-024 несёт `lost` = «якорь искали и не
   нашли». При переносе искать было нечего: чужая расшифровка никогда не
   была своей. Такая метка попала бы в счётчик «проверьте N меток» — работа
   автору на ровном месте.* Вдобавок противоречит решению владельца о
   головке: время у слайда одно, назначить его могут либо головка, либо
   слово источника, но не оба. Контроллер; владелец подтвердил вариант
   «строить время заново» → ADR-025.

5. **`freeId` заполняет дыры** (`elements.ts:25` — цикл с первого свободного
   номера). *После удаления `text-1` следующий текстовый элемент получит
   ТОТ ЖЕ `text-1`. Значит «переиспользовать элемент по совпадению id»
   пришило бы вставленный слайд к чужому элементу — правдоподобная
   подстановка вместо проверяемой.* Отсюда правило вставки из трёх случаев
   (id занят тем же / id свободен / id занят другим). Контроллер, чтением.

6. **История хранит `History<Project>`, а не `History<EditorState>`**
   (`editorHistory.ts:67`). *Буфер обмена ложится рядом с `lastRetarget`,
   вне истории. Отличие от `lastRetarget`: тот сбрасывается при undo/redo,
   буфер — нет. Буфер это предмет в руке, а не отчёт о правке, от которой
   автор отошёл.* Контроллер, чтением.

7. **Новых фикстур не требуется.** `demo.json` — 15 слайдов, 100+ слов;
   `repeat.json` — три части, `words: 0` (законный путь «часть без
   расшифровки»), id элементов НЕ пересекаются (`bg-a` / `bg-b`).
   *Каждая новая фикстура стоит пяти скриншотных эталонов и заведомо
   красного первого прогона.* Контроллер, чтением файлов, а не по памяти.

24. **Панель кнопок отняла у сцены 44 px, и это уронило ДВА e2e — оба

    живёт только в браузере.*

    Первое падение — «область сцены получает целые размеры»: моя строка
    причины имела `font-size: 12px; line-height: 1.4` = **16.8 px**,
    величину, не представимую в сетке 1/64 px, которой Chrome меряет
    раскладку. Дробь протекала вверх по flex-колонке. Комментарий самого
    теста предсказывает этот класс дословно. Починено целым `line-height`.

    Второе — «ручка меняет размер»: **три гипотезы подряд оказались
    неверны, и каждую опроверг замер, а не рассуждение.**

    | Гипотеза | Чем опровергнута |
    |---|---|
    | «элемент упёрся в край сцены» | `x=160`, предел был бы 1760, получено 1891.51 |
    | «сцена ограничена шириной, высота не важна» | верно при 1879 px окна, но e2e идёт при **1280×800**, где ограничение — ВЫСОТА |
    | «виноват перевод координат» | ошибка — доли пикселя ввода, арифметика точна |

    Настоящая причина, числами: до сессии сцена была ограничена шириной,
    масштаб `400/1920 = 0.208333`, и 100 экранных px давали **ровно 480**
    сценических единиц. Панель отняла 44 px, ограничение стало по высоте,
    масштаб `219/1080 = 0.202778`, 100 px стали давать **493.151**, и тот
    же подпиксельный остаток вырос до 1.64 единицы при жёстком допуске 0.05.

    **Решение владельца: принять цену, починить ИЗМЕРЕНИЕ.** Допуск теперь
    считается от масштаба — один экранный пиксель, переведённый в
    сценические единицы, — а не числом. Прецедент вписан в сам тест
    с Сессии 12: «округляется точка захвата, а не ослабляется утверждение».
    **Доказано сломом:** ошибка масштаба в 2 % даёт промах 39 единиц при
    допуске 4.93 — тест ловит.
