# Что Canva реально отдаёт наружу — замер 13.08.2026

Проверено живым подключением к аккаунту владельца через Canva MCP.
Три дизайна, все транзакции **отменены**, ни один дизайн не изменён.

Замер сделан потому, что «импорт из Канвы» стоял в MVP как пункт, про
который никто не знал, возможен ли он вообще. Планировать сессию под
недоказанную возможность — та же ошибка, что уже трижды стоила времени.

---

## 1. Два канала, и они дают РАЗНОЕ

### `get-design-content` — только текст

Возвращает **голый текст без единого атрибута**: ни координат, ни размера,
ни шрифта, ни цвета. Строки подряд, порядок примерно по чтению.

Для импорта бесполезен: восстановить по нему слайд нельзя.

### `start-editing-transaction` — скелет с геометрией

Возвращает на каждый элемент:

```
element_id
page_index
containerElement { type: 'TEXT' | 'RECT',
                   position:  { top, left },
                   dimension: { width, height } }
richtexts[].regions[] { type: 'character', text }
fills[]               { type: 'image', asset_id, editable, containerElement }
pages[]               { page_id, page_number, notes, dimension, is_empty }
thumbnails[]          { url }
```

---

## 2. Что отдаётся — проверено на настоящем дизайне

| что | отдаётся | пример из замера |
|---|---|---|
| положение элемента | **да**, в пикселях страницы | `top: 228.25, left: 100` |
| размер элемента | **да** | `width: 1400, height: 559.76` |
| текст | **да** | «Агентство: экономика, проценты, организация» |
| размер страницы | **да** | **1920 × 1080** |
| картинка | **ссылкой** `asset_id` | `MAFRacqM5MQ` |
| заметки докладчика | ~~да, на каждой странице~~ **см. поправку ниже** | ~~26 страниц из 26~~ **на самом деле 0 из 26** |
| границы выделения внутри абзаца | **да, но без самого выделения** | один абзац пришёл пятью кусками |

## 3. Чего НЕ отдаётся вовсе

**Ни одного признака внешнего вида.**

- шрифт, кегль, начертание, межстрочный интервал;
- цвет текста, цвет заливки, обводка;
- выравнивание внутри блока;
- поворот, прозрачность;
- **порядок слоёв** — значит перекрывающиеся элементы лягут как попало;
- фигуры как фигуры: всё непрямоугольное приходит как `RECT`;
- байты картинок — только `asset_id`, отдельного способа получить файл
  в этом канале нет.

**Вывод одной строкой:** Canva отдаёт **скелет** — прямоугольники
с координатами и текст внутри них, — но **не отдаёт вид**.

## 4. Две находки, которых никто не ждал

**Страница ровно 1920 × 1080 — это наша сцена.** Совпадение точное,
координаты переносятся один к одному, без масштабирования и без
накопления ошибки. Одной проблемой импорта меньше, и она была бы не
из мелких.

**Заметки докладчика отдаются на каждой странице.** В замеренном дизайне
их несли **все 26 страниц**, и это осмысленный текст автора о том, что
он собирается сказать на этом слайде.

> **ИСПРАВЛЕНО 15.08.2026, Сессия 40. Это утверждение НЕВЕРНО.**
>
> На том же самом дизайне `DAHRJ-GDk9U` заметок **ноль из 26**. Проверено
> четырьмя способами: `get-presenter-notes` возвращает 26 страниц без
> единого поля `notes`; в `pages[]` ответа `start-editing-transaction`
> поля `notes` нет вовсе; в pptx-выгрузке нет каталога `ppt/notesSlides/`;
> библиотека разбора даёт `null` на всех 26. Заметок нет и ещё на двух
> презентациях аккаунта.
>
> Похоже, тогда посчитали НАЛИЧИЕ ПОЛЯ в схеме ответа за наличие текста.
> Утверждение прожило два дня и успело стать «главной мыслью» Сессии 40:
> промпт был написан вокруг заметок, а их не существует.
>
> **Инструмент при этом исправен** — положительный контроль поставлен
> руками 15.08.2026: заметка, вписанная в Canva через браузер, читается
> и по каналу MCP, и из pptx-выгрузки, дословно. То есть заметки доезжают,
> когда они есть; у владельца их нет.
>
> Отсюда же снимается опасение §5.1 про склейку двух источников: второй
> канал не понадобился вовсе. → [ADR-031](../adr/ADR-031-pptx-import.md)

Это буквально `speech` нашей схемы. То есть импорт способен принести
не только картинку слайда, но и **текст озвучки к нему** — а от текста
озвучки у нас уже построен путь к синтезу голоса и к меткам.

## 5. Третий путь: экспорт в PPTX

Проверено: у замеренного дизайна доступны форматы
`pdf, jpg, png, pptx, gif, mp4` — **pptx поддерживается**.

PPTX — это zip с XML, где лежит всё, чего не даёт MCP: шрифты, кегли,
цвета, порядок слоёв, повороты, сами картинки файлами. Цена — разбор
формата OOXML.

### 5.1. Research по библиотекам — сделан 13.08.2026

Решение владельца: сначала выяснить, есть ли чем читать pptx, потом
выбирать путь. Проверено по первоисточникам — реестр npm и GitHub API,
не по описаниям в поиске.

| пакет | лицензия | версия | геометрия | оформление |
|---|---|---|---|---|
| **`pptx-viewer-core`** | **Apache-2.0** | 2.3.5 | **да** — позиции и размеры в EMU | да |
| `officeparser` | MIT | 7.5.1 | **нет** | да — жирность, цвет, кегль, шрифт, выравнивание |

**`officeparser` — зеркальное отражение канала MCP.** Он даёт ровно то,
чего MCP не даёт (шрифты и цвета), и не даёт ровно того, что MCP даёт
(координаты). Соблазн «взять оба и склеить» надо назвать и отвергнуть:
общих идентификаторов у двух источников нет, сопоставлять элементы
пришлось бы по совпадению текста — то есть правдоподобно и неверно.

**`pptx-viewer-core` — единственный кандидат.** Лицензия Apache-2.0,
запретов на визуальные редакторы в ней нет (в отличие от GSAP).

**Риск назван вслух: библиотека молодая.** Репозиторий заведён
**16.03.2026**, то есть ему пять месяцев; 61 звезда, один сопровождающий,
одна открытая заявка, не заархивирован, последняя запись в репозиторий —
**13.08.2026, в день проверки**. Живая и активная, но без истории.
Смягчается лицензией: Apache-2.0 позволяет форкнуть и вести у себя,
если сопровождение прекратится.

**Чего research НЕ доказал.** Что библиотека действительно отдаёт
координаты, шрифты, цвета и порядок слоёв **на нашем материале**.
README это утверждает; README — не прогон. Перед ADR нужен спайк:
выгрузить настоящую презентацию владельца из Canva в pptx, прогнать
через библиотеку и сверить с исходником числами. Это тот самый случай,
когда «в документации написано» не принимается.

## 6. Три возможных импорта и что автор получит

| путь | что автор получит | чего не получит |
|---|---|---|
| **А. Картинка** (png постранично) | точный вид, один в один | ни одного объекта: анимировать нечего, продукт теряет смысл |
| **Б. Скелет** (MCP) | объекты на своих местах, текст, заметки → озвучка | вид: шрифты, цвета, слои. Придётся оформлять заново |
| **В. PPTX** | вид и объекты | нужен разбор формата и, возможно, новая зависимость через ADR |

**Чего НЕ бывает:** пути, который даёт и вид, и объекты, и не стоит
разбора формата. Это надо принять как данность замера, а не искать
дальше.

## 7. Как это проверялось

Три дизайна аккаунта, все транзакции закрыты `cancel-editing-transaction`:

- одностраничный без текста — проверялась выдача геометрии картинок;
- двухстраничный без текста — проверялось поведение на пустой странице;
- 26-страничный текстовый — проверялась выдача текста, заметок и границ
  выделения.

Ни один дизайн не изменён.
