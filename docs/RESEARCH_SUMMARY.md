## О чём вообще проект

Интерактивные объяснения в вебе. Выглядит как видео — озвучка, таймлайн, анимации, — но внутри DOM (HTML-элементы), поэтому зритель может взаимодействовать: отвечать на вопросы, вводить текст, кликать.

Автор ставит на таймлайне **гейты** — точки, где плеер останавливается и открывает взаимодействие. Вне гейтов кликать нельзя физически.

---

## На какой стадии проект

**Работает сквозной срез плеера.** Можно взять фикстуру (JSON-файл с описанием проекта), загрузить её в плеер, нажать play — звук идёт, анимации синхронно двигаются, на гейте плеер останавливается, можно ответить, и продолжается с той же секунды. Подтверждено 43 e2e-тестами + 34 юнитами.

**Редактор написан, но не закончен.** Можно открыть проект, увидеть сцену, таскать элементы мышью, менять размеры/поворот, смотреть панель свойств. Дорожка с волной, перемотка, транскрипт — есть. Но:
- Нельзя добавлять/удалять элементы
- Нельзя редактировать анимации и гейты
- Нельзя сохранять проект

**Загрузки аудио пользователем нет.** Тайминги слов уже есть в фикстурах — их получают внешними инструментами (Deepgram, MFA), но кода для этого нет.

**Бэкенда нет.**

## Как это устроено: пакеты

### 1. `packages/core` — схемы, типы, валидация, время

Самое дно. Не знает про DOM, React, аудио. Чистая логика.

**Файлы:**
- `schema.ts` — ВСЯ схема проекта на Zod. Типы выводятся через `z.infer`. Никаких рукописных типов.
- `time.ts` — разрешение `TimeRef` (ссылок на время) в секунды. Только здесь можно превратить «слово №5 + смещение 0.1 с» в число.
- `load.ts` — загрузка проекта: миграция → валидация. Падает громко.
- `migrations.ts` — механизм миграций схемы. Сейчас есть только версия 1, миграций нет, но механизм готов.

**Сущности схемы:**
```
Project → meta, audio, scene
  audio → src (путь), duration, words[]
  scene → elements[], cues[], gates[]
    Element → id, type (text/image/shape/group), x, y, width, height, rotation, zIndex, style, content
    Cue → id, at (TimeRef), targetId, animation
      AnimationSpec → property, from?, to, duration, ease
    Gate → id, at (TimeRef), config (choice|input|continue), onWrong, maxAttempts
```

**TimeRef** — ключевая штука. Это не просто число, а размеченное объединение:
- `{ kind: 'seconds', t: number }` — время в секундах
- `{ kind: 'word', wordIndex, offset, anchor }` — привязка к слову с якорем (само слово + соседи слева/справа в нормализованном виде)

Это нужно, чтобы метки времени не уезжали, когда автор правит текст или меняет голос озвучки.

**Слова (Word):** `{ text, start, end, source, confidence? }`. `source` — откуда взялись тайминги: alignment (выравнивание), tts (синтез), manual (вручную). Разные источники дают разную точность.

**Что анимируется (инвариант №8):** только `x, y, scale, scaleX, scaleY, rotate, opacity, filter`. Всё остальное уводит с композитора браузера и роняет кадры. Это зашито в схему как закрытое перечисление.

### 2. `packages/player` — рантайм плеера

Собирается в самостоятельный ESM-бандл (152 КБ, 42 КБ в сжатом). Без React, без фреймворков.

**Файлы:**

`clock.ts` — **часы от аудио.** Вся механика времени:
- Дорожка декодируется целиком (`decodeAudioData`), играет через `AudioBufferSourceNode`
- В момент старта фиксируется **якорь** — пара `(контекстное время, позиция в дорожке)`
- Позиция считается: `позиция = якорь.mediaTime + (текущееКонтекстноеВремя - якорь.ctxTime)`
- `getOutputTimestamp()` — время сэмпла, который звучит прямо сейчас (а не `currentTime`, который отдан подсистеме)
- Задержка читается каждый кадр, а не один раз
- `freezeAt(t)` — останавливает время РОВНО на t. Логическое время записывается явно, звук глушится рампой (8 мс), контекст засыпает
- `resumeFromFreeze()` — просыпается, новый источник, рампа нарастания, та же позиция
- `seek(position)` — перемотка (только для редактора, у плеера её нет)

`render.ts` — **единственная функция рендера сцены.** Не знает про React и аудио:
- `renderScene(host, scene, stageSize)` — строит DOM внутри контейнера, возвращает карту `id → HTMLElement`
- `applyElement(node, element)` — переносит описание элемента в inline-стиль узла. Публичная, чтобы редактор мог точечно править один элемент
- `applyFit(host, hostWidth, hostHeight, stageSize)` — вписывает сцену в контейнер через `transform: translate(X, Y) scale(k)`
- Сцена имеет логический размер 1920×1080, масштабируется через `transform`, а не `zoom`

`timeline.ts` — **ведомый таймлайн:**
- Главный цикл anime.js глобально выключен (`engine.useDefaultMainLoop = false`)
- Каждый кадр: `tl.currentTime = position * 1000`
- `seekSeconds(seconds)` — двигает время вперёд (для плеера)
- `renderAt(seconds)` — приводит сцену к моменту через проход через ноль (для редактора и скриншотов)
- Начальное состояние анимаций выставляется явно нулевыми кадрами

`player.ts` — **склейка всего:**
- `Player` — класс, конструируется с host-контейнером и проектом
- `load()` — загружает аудио, строит сцену, таймлайн, сортирует гейты
- `play()` — начинает/продолжает воспроизведение
- `answer(value)` — принимает ответ зрителя, возвращает разбор попытки
- Состояния: `idle → loading → ready → playing → at-gate → ended`
- Player НЕ УМЕЕТ перемотки и паузы — это осознанно

`preview.ts` — **немой предпросмотр (без звука):**
- `ScenePreview` — сцена на заданном моменте, без аудио
- `segmentOf(project)` — единственная точка доступа к `project.audio` и `project.scene`
- `updateElement(element)` — точечная правка узла без пересборки сцены

### 3. `packages/editor` — React-редактор

**Файлы:**

`index.ts` — точка входа. `mountEditor(host, project, options)` — монтирует React-корень в контейнер.

`Editor.tsx` — корень редактора. Держит состояние через `useReducer` и `segmentOf`. Компоновка: сцена (`StageView`) + панель свойств (`Inspector`) + дорожка (`TrackView`).

`state/project.ts` — **единственное место, где проект пишется:** редьюсер с действиями `select`, `replaceElement`. Ссылочная целостность — важна для производительности (сравнение ссылок при перетаскивании).

`stage/StageView.tsx` — **сцена в редакторе:**
- React владеет ТОЛЬКО двумя пустыми контейнерами и оверлеем. Содержимое сцены строит `ScenePreview` из плеера
- Сцена пересобирается только при структурной правке (добавление/удаление элемента, смена размера сцены)
- Точечное обновление — через `updateElement`
- Жесты: выделение по клику, перетаскивание по `body`, изменение размера через ручки, поворот

`stage/geometry.ts` — перевод между координатными пространствами:
- **Логическое (сцена):** `element.x/y/width/height`, `offsetLeft`, `clientWidth`
- **Экранное (клиент):** `clientX/clientY`, `getBoundingClientRect()`
- Функции: `toScene`, `toScreen`, `boxToScreen`, `hitTest`, `topmostAt`, `rotate`
- Все чистые, без DOM

`stage/transform.ts` — преобразования элемента (перетаскивание, ресайз, поворот) в координатах сцены.

`stage/Overlay.tsx` — рамка выделения и ручки. Живут ПОВЕРХ сцены, а не внутри неё.

`track/Transport.ts` — транспорт редактора (воспроизведение, пауза, перемотка). Использует `AudioClock` из плеера. Умеет перемотку (в отличие от Player).

`track/useTransport.ts` — связка транспорта с React. Подписка на события, вычисление пиков волны.

`track/peaks.ts` — вычисление пиков звуковой волны: один проход по Float32Array.

`track/Waveform.tsx` — канва-компонент волны.

`track/TrackView.tsx` — дорожка: волна, головка, перемотка мышью, линейка, транскрипт.

`panels/Inspector.tsx` — панель свойств выделенного элемента. Числовые поля с черновиком.

`styles.ts` — CSS редактора строкой (чтобы встраивание не требовало обработки CSS).

## Как всё работает вместе (поток)

1. **Загрузка:** JSON → `loadProject()` (миграция + валидация) → если бито — громкая ошибка
2. **Инициализация:** `Player.load()` → `renderScene()` строит DOM → `loadTrack()` декодирует аудио → `buildTimeline()` создаёт таймлайн → гейты разрешаются в секунды → нулевой кадр отрисовывается
3. **Воспроизведение:** `Player.play()` → `AudioClock.start()` → `requestAnimationFrame` цикл → каждый кадр: `clock.position` → `timeline.seekSeconds(position)` → проверка гейта → проверка конца
4. **Гейт:** позиция ≥ времени гейта → `clock.freezeAt(time)` (логическое время = time, рампа в ноль, ctx.suspend()) → `timeline.seekSeconds(time)` → `pointerEvents = 'auto'` → событие `onGateOpen`
5. **Ответ:** `Player.answer(value)` → проверка правильности → если continue — `clock.resumeFromFreeze()` → новый источник, та же позиция, рампа нарастания → `pointerEvents = 'none'` → rAF цикл продолжается
6. **Редактор:** `Editor` через `segmentOf()` получает сегмент → `StageView` создаёт `ScenePreview` → пользователь таскает элементы → `updateElement()` точечно правит DOM → редьюсер обновляет состояние

## Инварианты (законы, которые нельзя нарушать)

1. **Аудио — единственный источник времени.** Никакой `setInterval`, счётчик кадров или отдельный таймер.
2. **Таймлайн ведомый.** Создаётся в паузе, никогда не играет сам.
3. **Гейт — единственный способ дать интерактив.** Вне гейта `pointer-events: none` у сцены.
4. **Гейт останавливает всё сразу.** Аудио, таймлайн, время. Возобновление с той же позиции. Перемотки нет.
5. **Один рендер на редактор и плеер.** Редактор импортирует `renderScene` из плеера. Двух реализаций нет.
6. **Направление зависимостей:** `editor → player → core`. Обратных импортов нет.
7. **Схема версионируется.** Изменение = бамп версии + миграция + фикстура + тест.
8. **Анимируем только `transform`, `opacity`, `filter`.**
9. **Плеер собирается без фреймворка** в ESM-бандл и работает в голом HTML.
10. **Метки времени привязаны к словам**, а не к миллисекундам.

## Что НЕ сделано

- [ ] **Редактор не дописан.** Нет: добавления/удаления элементов, редактора анимаций, редактора гейтов, сохранения проекта

- [ ] **Загрузка аудио и получение таймингов.** Есть измерения (S5), но кода нет
- [ ] **Прогон на живом Android**
- [ ] **Всё, что касается iOS** — долг. Нет устройства, не проверено поведение AudioContext
- [ ] **Один выброс в S5** — слово, промахнувшееся больше чем на 300 мс
- [ ] **Выборка арбитра в S5 мала** — выводы о p95 < 150 мс опираются на 3 и 9 слов
- [ ] **`filter: blur()` без запаса** — удваивает длину кадра, при росте числа блюров запас исчезнет первым
- [ ] **Нет ветвлений (нодов)** — запланировано на будущее, сейчас одна дорожка

## Что дальше (по плану)

Следующий шаг — **дописать редактор**: слайдовая сцена, дорожка аудио снизу, метки анимаций и гейтов на ней. Редактор обязан:
1. Импортировать `renderScene` из плеера (инвариант №5)
2. Ходить в проект через `segmentOf` (а не напрямую к `project.audio`/`project.scene`)

Страховка уже стоит: `ScenePreview` умеет ставить сцену на любой момент и точечно править узел, 25 эталонов ловят поломки рендера.

## Как собрать и запустить

```
pnpm install          # установка
pnpm dev              # дев-сервер → http://localhost:5179/
                        # ?fixture=e2e — другая фикстура
pnpm check            # все проверки: типы → юниты → сборка → e2e
pnpm build:player     # сборка плеера в public/bundle/player.js
```
