# Сессия 15: текст озвучки, выравнивание, повтор и копия куска

> **Для исполнителя:** ОБЯЗАТЕЛЬНАЯ ПОД-СКИЛЛ: `superpowers:subagent-driven-development`
> (рекомендуется) или `superpowers:executing-plans`. Шаги отмечаются чекбоксами.

**Цель:** ввести в схему текст озвучки (v7), вплести `alignWords` в замену
озвучки, закрыть пункт 35 списка-сторожа (повтор куска и копия куска).

**Спецификация:** [ADR-022](../../adr/ADR-022-speech-and-script.md).
Всё, что там записано, — обязательно; всё, чего там нет, — вне объёма.

**Архитектура.** Три независимые части. Часть A трогает схему и разрез,
часть B — редактор и `core/align.ts`, часть C — плеер и состояние редактора.
Между A, B и C нет зависимостей по коду: B работает на схеме v6, C схемы
не касается вовсе. Порядок в плане — от самого рискованного к самому
дешёвому, чтобы срезать при нехватке времени было что, а не кого.

**Стек:** TypeScript, Zod v4, Vitest, Playwright, React 19, pnpm workspaces.

## Глобальные ограничения

Действуют в каждой задаче, повторять в каждой не будем.

- **Инвариант №7.** Изменение схемы = бамп версии + функция миграции +
  фикстура + тест. Без исключений.
- **Инвариант №6.** Направление зависимостей `editor → player → core`.
  Обратных импортов нет, `core` не знает про DOM и React.
- **Инвариант №1 и №4.** Аудио — единственный источник времени. Гейт
  останавливает всё сразу, перемотки не происходит никогда.
- **Словарь.** В интерфейсе нет слов схемы. Пишем «текст озвучки»,
  «расшифровка», «кусок», «остановка», «зритель». Слов `lesson`, `section`,
  «урок», «ученик», «раздел» нет нигде — ни в коде, ни в тексте на экране.
- **Слово «сценарий» закреплено за планом объяснения** (ADR-022) и в этой
  сессии в схеме не появляется ни в каком виде.
- **`pnpm check` после каждой задачи.** Смотреть на числа в выводе, а не на
  код возврата: `cmd | tail` возвращает код `tail`, а `cmd > log; echo $?` —
  код `echo`. Оба уже давали ложную зелень.
- **Эталонные фикстуры в `fixtures/projects/` руками не править.** Новые —
  можно создавать. Существующие — только скриптом и с объяснением.
- **Дорожки веток (`ask.mp3`, `branch-yes.mp3`, `branch-no.mp3`) не удлинять
  и не заменять.** Их длина ~3 с вписана в `e2e/editor-segments.spec.ts:112`.
- **Новых зависимостей не добавлять.**
- Тесты запускаются: `pnpm exec vitest run -t "часть названия"`,
  `pnpm exec playwright test -g "часть названия"`.

```ts
/**
 * Единственное место, где текст озвучки режется на слова.
 *
 * Единственное — не для красоты. `CLAUDE.md`: разные инструменты по-разному

 * при сравнении, и делать это дважды разными способами значило бы завести
 * второе правило нормализации.

export function splitIntoWords(text: string): { text: string }[] {
  return text.split(/\s+/u).filter((word) => word.length > 0).map((word) => ({ text: word }));
}
```

```ts
/**
 * Сколько первых слов текста озвучки достаётся голове.
 *
 * `undefined` — делить нечем, и это не ошибка: либо речи нет вовсе, либо
 * нет расшифровки, а без неё шва не существует. Оба случая законны, и оба
 * обязаны быть видимы снаружи, а не свёрнуты в ноль.
 */
function speechCutIndex(
  speech: string | undefined,
  words: readonly Word[],
  wordsCut: number,
): number | undefined {
  if (speech === undefined || words.length === 0) return undefined;

  const spoken = splitIntoWords(speech);
  const ops = alignWords(spoken, words);

  // Первая операция, которая указывает на слово расшифровки за швом,
  // и даёт границу речи. Идём слева направо: операции возвращаются
  // в порядке нового транскрипта (см. `align.ts`).
  for (const op of ops) {
    const newIndex = op.kind === 'removed' ? undefined : op.newIndex;
    if (newIndex !== undefined && newIndex >= wordsCut) {
      return op.kind === 'added' ? spoken.length : op.oldIndex;
    }
  }
  return spoken.length;
}
```

### Задача 9: повтор куска в плеере

**Файлы:**
- Изменить: `packages/player/src/player.ts` (`#mountSegment` около строки 364;

- Тест: `packages/player/test/player.test.ts` (или тот файл, где уже живут
  тесты переходов — найти: `grep -rl "goToNode\|nextSegment" packages/player/test`)
- Тест: `e2e/player-repeat.spec.ts` (создать)

**Решение владельца 02.08.2026, дословно по смыслу:** остановки ВНУТРИ
повторяемого куска не открываются; остановка, которая отправила на повтор,
спрашивает снова. От вечной петли защищает `maxAttempts`, который у гейта
в схеме уже есть.

**Механика.** Остановка молчит тогда и только тогда, когда на неё **уже
отвечали в этом просмотре**. Отдельного «посещён» для гейтов не нужно:
ответ и есть след. Виновная остановка спрашивает снова, потому что при уходе
на повтор её ответ **стирается** — стирается ровно та переменная, которую
прочитало сработавшее правило.

**Почему не «сегмент уже посещён».** Кусок, откуда зритель ушёл на повтор,
тоже станет посещённым, и его остановка замолчала бы вместе с остальными —
то есть возвращаться было бы незачем.

**Почему не трогает `assume.answers`.** Предпросмотр «смотреть как зритель,
ответивший X» засевает `#answers` заранее (`player.ts:228`). Если считать
следом сам ответ, эти остановки замолчали бы и сломали существующие e2e.
Поэтому след — отдельное множество **идентификаторов остановок, отвеченных
в этом просмотре**, а не наличие значения в `#answers`.

**Интерфейсы:**
- Потребляет: `nextExit` (задача 8).
- Производит: `Player.isRepeating: boolean` — читает вид, чтобы показать

```ts
  /**
   * Отмечает переход и решает, повтор ли это.
   *
   * Повтор — это возвращение в уже слышанный кусок. Определяется по факту,
   * а не по разметке автора: правило выхода не знает, вперёд оно ведёт или
   * назад, и знать не может — граф не дерево.
   */
  #enterSegment(nodeId: string, choice: ExitChoice | null): void {
    this.#repeating = this.#visited.has(nodeId);
    this.#visited.add(nodeId);

    if (!this.#repeating || !choice?.rule) return;

    // Виновница спрашивает снова. Стираем след ровно тех остановок, чьи
    // ответы прочитало сработавшее правило: иначе возвращаться было бы
    // незачем — зритель попал бы в ту же развилку с тем же ответом
    // и уехал на повтор ещё раз, и так навсегда.
    const read = new Set(choice.rule.when.map((condition) => condition.variable));
    for (const segment of this.#project.segments) {
      for (const gate of segment.gates) {
        if (read.has(gate.recordAs)) this.#answeredHere.delete(gate.id);
      }
    }
  }
```

  и повтор не повод заводить её целиком.

  за пределами файла, запись байтов до подтверждения замены.
