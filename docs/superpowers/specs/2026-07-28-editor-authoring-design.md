# Сессия 3: редактор становится инструментом создания

Дата: 2026-07-28. Статус: на согласовании.

## Цель

Автор делает объяснение с нуля, ни разу не открыв JSON.

Проверяемо это означает: открыть проект с озвучкой и пустой сценой, создать
в редакторе элемент, задать ему вид, повесить анимацию, поставить гейт
с вопросом — и получить файл, который плеер играет, а `loadProject` принимает.

## Продуктовая рамка

Продукт — не видеоредактор. Автор собирает объяснение как презентацию: холст
первичен, время вторично. Зритель видит ролик, но может ткнуть прямо в него.

Из этого следуют два решения, которые в коде сейчас нарушены, и обе поломки
чинятся в этой сессии.

### Интерактив живёт внутри сцены, а не поверх неё

Сейчас гейт для зрителя — модальная плашка, затемняющая сцену. Она нарисована
не плеером, а дев-стендом (`apps/playground/src/main.ts`, `showGate`): `Player`
только сообщает наружу `GateAttempt` через `onGateResolved`. То есть вид гейта
никогда не был решением — это заглушка оснастки.

**Решение: гибрид.** Если `option.id` совпадает с `id` элемента сцены,
вариантом ответа служит сам элемент, нарисованный автором. Если совпадения нет,
плеер сообщает об этом наружу, и оснастка рисует кнопку, как сейчас.

Схема не меняется. `ChoiceConfig.options[].id` имеет тип `Id` — обычный
идентификатор внутри проекта, и схема нигде не требует, чтобы он не совпадал
с идентификатором элемента. Ссылкой его делает совпадение.

Отсюда важное свойство: **удаление элемента-варианта не ломает проект**.
`option` остаётся в гейте, `correctId` по-прежнему указывает на существующий
вариант, валидация проходит, вариант деградирует до системной кнопки.

Решение оформляется как ADR-011.

### Холст — рабочая поверхность, а не предпросмотр

Сейчас редактор — инспектор чисел: выделил элемент, правишь `x`, `y`, `zIndex`
в форме справа. Создать элемент нельзя, стиль недоступен, текст правится
в текстовом поле панели мелким моноширинным шрифтом, а на сцене он в 72 px.

В этой сессии холст получает: создание и удаление элементов, правку текста
на месте по двойному клику, стиль, отмену и клавиатуру. Внешний вид редактора
не переписывается — это отдельная сессия. Здесь интерфейс становится
функциональнее, а не красивее.

## Что менять нельзя

Схема. `SCHEMA_VERSION` остаётся `1`. Проверено: всё нужное уже есть —
три вида гейта в `discriminatedUnion` (`continue` / `choice` / `input`),
`onWrong`, `maxAttempts`, `style` как свободная карта `Record<string, string|number>`,
`type: 'text' | 'image' | 'shape' | 'group'`, `ANIMATABLE` из восьми свойств.
Если по ходу покажется, что поля не хватает — остановиться и спросить.

Инварианты 1–10. Отдельно под наблюдением в этой сессии: №3 (недоступность
вне гейта физическая), №5 (один рендер), №6 (список импортов редактора),
№8 (перечень анимируемых свойств).

Эталонные фикстуры в `fixtures/projects/`. Добавление новой — можно,
правка существующих — нет.

## Порядок срезов

Один вертикальный срез за раз, каждый до работающего состояния,
`pnpm check` после каждого.

Против задания сессии сдвинут один шаг: **отмена переехала с пятого места
на второе**. Удаление — первая необратимая операция, без Ctrl+Z её опасно
проверять руками; и каждый следующий срез получает отмену даром, тогда как
ретрофит истории после четырёх срезов означает переделку коммит-точек
в четырёх местах.

| # | Срез | Новое | Редьюсер |
|---|---|---|---|
| 1 | Создание, удаление, список элементов | `state/elements.ts` | `addElement`, `removeElement` |
| 2 | Отмена и повтор | `state/history.ts` | `undo`, `redo` |
| 3 | Настройка гейта | `state/gates.ts`, ADR-011 | `updateGate` |
| 4 | Настройка анимации | `state/animation.ts` | `updateCue` |
| 5 | Стиль элемента | `state/style.ts`, ADR-012 | через `replaceElement` |
| 6 | Клавиатура | `keyboard.ts` | — |

Список элементов входит в первый срез, а не в последний, хотя ближе по смыслу
к клавиатуре. Причина в разделе «Список элементов» ниже: без него элемент,
на который повешена анимация появления, теряется навсегда, а анимации
появляются уже в срезе 4. Создавать элементы раньше, чем появится способ
их найти, — значит делать срез, которым нельзя пользоваться.

Логика вся снаружи React, по ADR-010: чистые модули с юнит-тестами, компоненты
получают готовые данные пропсами и отдают события колбэками. Клавиатура —
именно таблица `keyToAction(event, context)`, а не обработчик: обработчик
исчезнет вместе с видом, таблица переживёт.

## Срез 1: создание и удаление элементов

**Новый модуль `state/elements.ts`** — чистый, без React и DOM.

Фабрики трёх видов. Новый элемент появляется в центре сцены, получает свободный
идентификатор через существующий `freeId`, сразу выделяется. Значения по
умолчанию берутся из существующих фикстур, чтобы созданный элемент выглядел
как соседи, а не как чужой:

- `text` — `font-family`, `font-size`, `color`, `line-height` из `demo.json`,
  `content` — заглушка, которую автор тут же перепишет двойным кликом;
- `shape` — прямоугольник с `background` и `border-radius` из `demo.json`;
- `image` — пустой `content`, ждёт файла.

Удаление с каскадом:

```ts
removeElement(scene, id): { scene: Scene, removedCues: readonly Cue[] }
```

Каскад обязателен, потому что `ProjectSchema.superRefine` требует
`cue.targetId ∈ elements[].id` — осиротевшая анимация означает, что проект
не загрузится вовсе. Автору сообщается, сколько анимаций удалено вместе
с элементом; Ctrl+Z (срез 2) возвращает всё целиком.

Гейты каскада не требуют: у `Gate` нет ссылок на элементы (см. рамку выше).

**Картинка.** Автор перетаскивает файл на холст, файл кодируется в base64
и ложится в `content` как data-URI. Проект становится самодостаточным
и работает офлайн — «один файл = одно объяснение». Однострочное поле `content`
для `image` в панели уже есть и остаётся: кто хочет вписать ссылку, впишет.

Известное следствие, которое чинится в этом же срезе, — см. раздел «Риски»,
пункт про `localStorage`.

**Новая фикстура `fixtures/projects/empty.json`** — озвучка
`audio/demo.mp3` (единственный аудиофайл на диске), пустые `elements`,
`cues`, `gates`. Это валидный проект и это стартовая точка автора.
Следствие: `e2e/fixtures.spec.ts` генерирует тесты перебором каталога, значит
появятся 5 новых скриншотных эталонов (пустая сцена на пяти моментах).
Это добавление, а не правка существующих эталонов.

## Срез 2: отмена и повтор

**Снимки состояний, не патчи. 50 шагов, кольцевой буфер.**

Обоснование по памяти: 20 КБ — размер JSON-текста, а не стоимость снимка.
Редьюсер уже иммутабельный и уже обязан сохранять ссылки на неизменившиеся
массивы, иначе `StageView` пересобирал бы сцену на каждое движение мыши. Правка
одного элемента порождает новый `project`, новый `scene`, новый массив
`elements` и новый элемент; `cues` и `gates` остаются теми же по ссылке. Цена
шага — сотни байт. Даже по верхней границе, если бы каждый снимок был полной
копией: 50 × 20 КБ = 1 МБ, что для вкладки браузера ничто.

Раз память не ограничивает, выбираем по надёжности, и снимки выигрывают
решительно: история патчей требует обратного патча на каждый тип действия,
ошибка в одном обратном патче портит проект тихо и находится через двадцать
шагов. Снимок не может быть неправильным.

**Модуль `state/history.ts`** — чистый:

```ts
interface History<T> { past: readonly T[]; present: T; future: readonly T[] }
push(h, next): History<T>   // future очищается
undo(h) / redo(h) / canUndo(h) / canRedo(h)
```

Три правила, каждое — тест:

1. **`select` в историю не пишется.** Иначе Ctrl+Z будет отменять клик, а не
   правку.
2. **Жест = один шаг.** Перетаскивание даёт десятки `replaceElement`.
   Коммит-точка явная, не эвристическая: `StageView` знает, где `pointerup`;
   панель свойств уже коммитит на blur через паттерн черновика в `NumberField`.
   Коалесценция «склеим подряд идущие правки одного элемента» отвергнута — она
   молча склеит две осознанные правки одного поля.
3. **Отмена не двигает время.** Восстановление старого `project` меняет ссылку
   на `elements`, `StageView` пересобирает сцену, свежий `ScenePreview` встаёт
   на ноль. Это ловушка, которая в прошлой сессии молча отматывала сцену
   в начало при добавлении метки. После отмены обязателен `renderAt(позиция)`,
   и на это отдельный e2e.

Данные, которые не являются проектом (выделение, позиция головки, выделенная
метка), в снимок не входят. После отмены выделение проверяется на существование:
если выделенного элемента в восстановленном проекте нет, выделение снимается.

## Срез 3: настройка гейта

**Модуль `state/gates.ts`** — чистый. Держит правила, которые обязаны пережить
переписку интерфейса:

- смена вида гейта с сохранением совместимых полей (`prompt` переносится между
  `choice` и `input`, не теряется при случайном переключении);
- добавление и удаление варианта; удаление варианта, на который указывает
  `correctId`, обязано переназначить `correctId` — иначе схема невалидна;
- минимум два варианта у `choice`, минимум один принимаемый ответ у `input` —
  это требования схемы, и модуль не даёт их нарушить;
- `bindOption(gate, optionId, elementId)` — привязка варианта к элементу сцены:
  переименовывает `option.id` в `elementId` и чинит `correctId`, если он
  указывал на старый идентификатор.

**Панель метки.** Сейчас метка на дорожке выделяется, но настраивать её нечем —
панель свойств продолжает показывать элемент. Появляется панель выделенной
метки: для гейта — вид, вопрос, варианты с привязкой к элементам, принимаемые
ответы, чувствительность к регистру, `onWrong`, `maxAttempts`. Плюс кнопка
удаления метки: `removeMark` в редьюсере есть и работает, кнопки к нему нет.

**Плеер (ADR-011).** Механика блокировки не меняется ни на строку. Сейчас
`pointer-events` переключается на контейнере `#stage` целиком: `none`
в конструкторе, `auto` в `#openGate`, `none` в `#leaveGate`. Гибрид ложится
поверх этого без правок:

- `Player` сохраняет карту узлов `Map<id, HTMLElement>` полем (сейчас `nodes` —
  локальная переменная `load()`);
- один делегированный обработчик вешается на `#stage` при загрузке и **никогда
  не снимается** (ADR-005): по клику берёт ближайший `[data-id]`, читает
  идентификатор, проверяет, что состояние `at-gate` и что текущий гейт содержит
  вариант с этим идентификатором, и вызывает `answer(id)`;
- недоступность вне гейта по-прежнему обеспечивает `pointer-events: none`
  на родителе — то есть инвариант №3 держится ровно тем же механизмом.

**Ловушка, которую здесь нельзя допустить:** не ставить `pointer-events: auto`
на отдельные узлы-варианты. `pointer-events` у потомка перебивает `none`
родителя, а тест инварианта №3 проверяет вычисленное значение на родителе
(`.player-stage`) и такой утечки не увидит. Вся блокировка остаётся на одном
узле.

Признак «этот элемент сейчас вариант ответа» плеер ставит через `dataset`,
а не через `className`: `applyElement` перезаписывает `className` целиком
и затрёт добавленный класс, а прочие `data`-атрибуты не трогает.

Наружу добавляется сообщение о том, какие варианты не нашли своего элемента —
их и только их оснастка дорисовывает кнопками.

Существующие фикстуры не содержат элементов, чей `id` совпадает с `option.id`,
поэтому все семь тестов `e2e/player.spec.ts` идут по старому пути и остаются
зелёными без правок. Новое поведение проверяется новыми тестами на новой
фикстуре.

## Срез 4: настройка анимации

**Модуль `state/animation.ts`** — чистый. Правка `AnimationSpec`: свойство
из `ANIMATABLE`, `from`, `to`, `duration`, `ease`.

Ключевое правило: **смена свойства сбрасывает `from`/`to` на осмысленные
для нового свойства**. `opacity` не принимает `blur(8px)`, `filter` не принимает
`0.5` как строку с единицами. Молчаливый перенос значения между свойствами
даст либо ошибку валидации, либо тихо неработающую анимацию.

ADR-009 не ломать: `buildTimeline` кладёт нулевой кадр с `from` в позицию 0
для каждой пары «элемент + свойство», побеждает самый ранний кью. Элемент
держится в состоянии `from` до старта — это уже работает и проверяется
`e2e/preview.spec.ts`.

Панель метки анимации: цель (какой элемент), свойство, значения, длительность,
плавность.

## Срез 5: стиль элемента

**Модуль `state/style.ts`** — чистый. Оформляется как ADR-012, потому что схема
ключи не ограничивает и набор полей — продуктовое решение.

**Правило отбора важнее списка: из полей стиля исключается всё, что есть
в `ANIMATABLE`.** Если автор выставит `opacity: 0.5` в стиле, а на элементе
висит анимация появления `opacity 0 → 1`, они молча подерутся за одно свойство
и победит анимация. Автор увидит, что поле «не работает», и не поймёт почему.
Прозрачность и блюр живут в анимации, положение и поворот — в геометрии.

Второе правило: ни одно поле не двигает раскладку за пределы бокса элемента —
`padding`, `margin`, `border` в набор не входят.

Набор на эту сессию, ключи kebab-case, как в существующих фикстурах:

| Поле | Ключ | Применимо |
|---|---|---|
| Шрифт | `font-family` | текст |
| Кегль | `font-size` | текст |
| Насыщенность | `font-weight` | текст |
| Цвет | `color` | текст |
| Выравнивание | `text-align` | текст |
| Межстрочный | `line-height` | текст |
| Фон | `background` | все |
| Скругление | `border-radius` | все |

Восемь полей. Расширение набора — правка ADR-012, не молчаливое добавление.

## Срез 6: клавиатура

**Модуль `keyboard.ts`** — чистая таблица `keyToAction(event, context)`.
Обработчик в компоненте только вызывает её и диспатчит результат.

- `Delete` / `Backspace` — удалить выделенный элемент;
- стрелки — сдвиг на 1 px, с `Shift` на 10 px, один шаг истории на серию;
- `Ctrl+Z` / `Ctrl+Shift+Z` — отмена и повтор;
- `Escape` — снять выделение, а в режиме правки текста — выйти из него;
- `Tab` — обход элементов сцены.

Обход с клавиатуры идёт по списку элементов из среза 1: список — обычные
фокусируемые кнопки, поэтому `Tab` работает без отдельной машинерии, а порядок
обхода совпадает с тем, что автор видит глазами. Отдельного roving-фокуса
по сцене не появляется: у сцены `pointer-events: none` и своих интерактивных
узлов у неё нет.

## Список элементов

Плоский перечень того, что есть на сцене, с выделением по клику и обходом
с клавиатуры. Входит в срез 1.

Он не украшение и не «панель слоёв на будущее» — он закрывает дыру, найденную
разведкой и отсутствующую в списке `status.md`:

> Единственный путь выделения — клик по сцене (`StageView.handleStageDown`),
> и на входе стоит фильтр `isVisible`: элемент попадает в хит-тест, только если
> `getComputedStyle(node).opacity > 0.01`. Логика правильная и обоснована
> в ADR-010 — она чинила реальный дефект. Но следствие: элемент, который
> на текущей секунде ещё не появился, **невозможно выделить вообще**. Автор
> создал заголовок, повесил появление на 10-й секунде, перемотал на 5-ю —
> и потерял его: ни подвинуть, ни покрасить, ни удалить.

Цель сессии — «автор делает объяснение с нуля», а начинается объяснение
с пустой сцены, где по определению почти всё ещё не появилось. Без второго пути
выделения цель недостижима.

Подсветка невидимых элементов «призраком» прямо на сцене рассмотрена
и отвергнута: редактор не имеет права рисовать элемент своей рукой, инвариант №5.

Список даёт три вещи одним куском: выделение невидимого, достижимость без мыши
и видимый глазами порядок слоёв вместо угадывания числа `z-index`.

## Правка текста на холсте

Двойной клик по текстовому элементу ставит каретку внутрь, автор правит текст
на месте, видя настоящий кегль, шрифт, перенос строк и ширину бокса.

Ложится чисто: `.scene-el` — обычный `div`, текст лежит прямо в его
`textContent`, шрифт и кегль из `element.style` применяются к тому же узлу,
и узел находится внутри поддерева, на котором висит `transform: scale()` —
значит каретка и набор будут в настоящем масштабе сцены.

Это не второй рендер и не нарушение инварианта №5: `contenteditable` —
атрибут на узле, который построил `renderScene`, ровно как `pointer-events`,
которым редактор уже управляет.

Три препятствия, у каждого уже есть образец решения в коде:

1. Сцене выставлен `pointer-events: none` скриптом (`StageView.tsx:159`) —
   на время правки снимается с одного узла и возвращается на коммите.
2. `user-select: none` наследуется от `.ed-root` (`styles.ts:21`) — нужно
   исключение; в файле уже есть два таких же, для `.ed-words` и полей
   инспектора.
3. `applyElement` делает **безусловный** `node.textContent = element.content` —
   это убьёт каретку, даже не пересоздавая узел. Правило жёсткое: пока каретка
   внутри, ни `updateElement`, ни `rebuild` этого узла не касаются. Источник
   истины остаётся `element.content`; DOM расходится с ним только на время
   жеста, как при перетаскивании.

Коммит — по `Escape` или клику мимо, один шаг истории на всю правку.

## Риски и ловушки

**data-URI ломает канал предпросмотра.** Круг «редактор → плеер» идёт через
`localStorage`: `openInPlayer` кладёт туда весь сериализованный проект
(`state/save.ts`). Сейчас это 20 КБ. С вшитыми картинками проект уходит
в мегабайты, а квота `localStorage` — единицы мегабайт на origin. Ломается
тихо: `setItem` бросит `QuotaExceededError`, а вкладка плеера всё равно
откроется и скажет «редактор не передал проект».

Порядок действий: сначала измерить реальную квоту в браузере, а не поверить
документации; потом выбрать лечение. Падать на превышении обязательно громко
и с внятным текстом. Без этого критерий приёмки «собранный в редакторе гейт
работает в плеере» не пройдёт на проекте с картинкой.

Лечения, между которыми выбираем после замера, в порядке предпочтения:

1. Уменьшать картинку при вставке до размеров сцены (1920×1080) через `canvas`
   и перекодировать. Устраняет причину: снимок экрана на 4 МБ становится
   парой сотен килобайт, а видимой разницы на сцене нет.
2. Заменить канал предпросмотра на тот, у которого нет квоты в мегабайтах —
   `BroadcastChannel` или `postMessage` в открытую вкладку. Чинит канал, но
   не чинит размер сохраняемого файла.
3. Ограничить размер вставляемого файла с честным отказом. Самое дешёвое
   и самое грубое: перекладывает проблему на автора.

Первое и второе не исключают друг друга. Решение записывается в ADR-012
или отдельным ADR — по итогам замера.

**Ссылочная целостность в редьюсере.** `StageView` решает, пересобирать сцену
или обновить один узел, сравнением ссылок. Новые действия обязаны сохранять
неизменившиеся массивы теми же по ссылке. Это несущая конструкция, а не
педантизм.

**Свежий `ScenePreview` стоит на нуле.** После любой структурной правки —
создание, удаление, отмена — время выставляется заново.

**Служебный текст не двигает раскладку.** У детей grid и flex минимальный
размер по умолчанию равен содержимому. Сообщение «удалено 3 анимации» и список
элементов обязаны иметь `min-width: 0` / `min-height: 0`, иначе раздвинут сетку
и сдвинут сцену прямо под курсором.

**Анимации проверяются покадрово.** При большом скачке anime.js форсирует
рендер, и сломанная реализация выглядит исправной.

**Координатные пространства не смешивать.** Масштаб берётся из DOM каждый раз,
перевод — только через `stage/geometry.ts`.

**Редьюсер без юнит-тестов.** `state/project.ts` сейчас проверяется только
через e2e; то же у `transport.ts` и `save.ts`. Вся новая логика сессии падает
именно в редьюсер, поэтому юниты на него — условие, а не «заодно».

## Тесты

**Юниты.** История: 20+ шагов туда-обратно, кольцо на 50, `future` затирается
новой правкой, жест даёт один шаг, `select` шага не даёт. Элементы: фабрики трёх
видов, свободный идентификатор, каскад возвращает список удалённых анимаций.
Гейты: смена вида сохраняет совместимые поля, `correctId` всегда валиден,
привязка варианта к элементу чинит `correctId`, минимумы схемы не нарушаются.
Анимация: валидный `AnimationSpec` для всех восьми значений `ANIMATABLE`.
Стиль: круговой проход значение → строка → значение; ни одно поле набора
не пересекается с `ANIMATABLE`. Клавиатура: таблица «клавиша + контекст →
действие».

**Охранник целостности.** Сценарий правок в редьюсере заканчивается
`loadProject(serializeProject(project))`. Ловит класс дефектов, а не один
случай.

**E2E, нажимая по видимым кнопкам.** Проверка «вызвался ли обработчик» зелена
при любом дефекте раскладки, масштаба и порядка эффектов.

- пустой проект наполняется целиком: элемент, текст в нём, анимация, гейт
  с вопросом — и сохранённый файл проходит `loadProject`;
- гейт с выбором варианта, собранный в редакторе, работает в плеере: неверный
  ответ не пропускает, верный пропускает;
- гейт с вводом слова принимает ответ; регистр учитывается по флагу;
- вариант ответа, привязанный к элементу сцены, кликается **на сцене**, сцена
  при этом не гаснет;
- вне гейта элемент-вариант кликов не получает — инвариант №3 на новом пути;
- удаление элемента с анимациями даёт файл, который грузится;
- анимация с правленым свойством видна на своей секунде и не видна до неё,
  проверка покадровая;
- правка стиля даёт одинаковый вид в редакторе и в плеере;
- двадцать отмен подряд не теряются; отмена не отматывает сцену в начало;
- правка текста на холсте: двойной клик, набор, коммит, паритет рендера после;
- элемент, невидимый на текущей секунде, выделяется через список;
- работа без мыши: Tab до сцены, стрелки на 1 и 10, Delete, Escape, Ctrl+Z;
- `schemaVersion` не изменился, список импортов редактора не вырос.

## Чего в этой сессии нет

Ветвления, ноды, граф сегментов, несколько дорожек. Бэкенд, база, авторизация,
публикация. Загрузка своего аудио и получение пословных таймингов. Резка
дорожки, громкость, фейды. Совместное редактирование, история версий.
AI-генерация, интеграции, экспорт в MP4. Множественное выделение, копирование,
дублирование, направляющие и привязка к сетке — они есть в списке дыр
`status.md`, но не в задаче сессии. Переписывание внешнего вида.
