## 1. Целевая раскладка

`.ed-root` — строки `auto 1fr auto` (без изменений).
`.ed-main` — колонки меняются:

```
было:  1fr 220px 260px          (обе боковые справа)
стало: 72px  350px  1fr  260px  (рельс, каталог, сцена, правая колонка)
       ^^^^  ^^^^^       ^^^^^
       рельс  каталог     слайды/сегменты/метки/элементы
```

Числа 72 и 350 — **замер каркаса** (журнал §1), не выдуманы.

Ширины задаются переменными на `.ed-root`, чтобы сворачивание и сжатие
меняли одну запись, а не перекладывали сетку:

```
--ed-rail-w: 72px;      /* не сворачивается: это дорога назад */
--ed-catalog-w: 350px;  /* 0 при свёрнутой панели, 260…560 при сжатии */
--ed-right-w: 260px;    /* 0 при свёрнутой, 200…420 при сжатии */
```

Сцена правки получает `1fr` и вырастает примерно с 480 до 760 px
при окне 1440.

## 3. ЗАКОН СЕССИИ: полоса свойств высоту НЕ меняет и НЕ сворачивается

Куплено дефектом Сессии 29 (журнал §8). Физика, а не правило:

> Автор делает двойной щелчок по элементу. Первый клик выделяет. Если
> от выделения обстановка под курсором меняется — появилась полоса или
> холст изменил размер и элемент уехал, — второй клик того же жеста
> попадает не туда. В прогоне двойной щелчок по заголовку нажал
> «выровнять по нижнему краю», и элемент уехал на низ холста.

Отсюда три запрета, обязательных к соблюдению:

1. высота полосы постоянна **всегда**, включая пустое выделение;
2. полоса не входит в сворачиваемые панели;
3. нажатия на самой полосе не всплывают в контейнер сцены — иначе сцена
   снимет выделение и полоса опустеет до срабатывания кнопки (журнал С29 §7).

Сворачивание панелей **по краям** этому не противоречит: оно происходит
от отдельного намеренного нажатия по кнопке, живущей ВНЕ холста, а не
само собой в середине жеста.

## 4. Задачи

### A. Новые компоненты хрома (файлы новые, чужого не трогает)

`packages/editor/src/chrome/` — новый каталог:

- `CatalogRail.tsx` — рельс. Кнопки категорий данными, `aria-pressed`
  у выбранной, `data-testid="rail-<id>"`.
- `CatalogPanel.tsx` — голова (заголовок + пояснение) и тело (`children`).
  `data-testid="catalog"`, `data-panel="<id>"`.
- `catalog.ts` — описание категорий данными: `id`, подпись, значок,
  пояснение. Ровно пять; «Объект» здесь НЕ значится.
- `Splitter.tsx` — перетаскиваемая граница. Принимает текущую ширину,
  минимум, максимум, сторону и колбэк. `role="separator"`,
  `aria-orientation="vertical"`, стрелки клавиатурой.

Ни одной правки в `Editor.tsx` и `styles.ts` — это задача B.

### B. Категории каталога — ДАННЫМИ

`state/library.ts`: каждой записи `ELEMENT_LIBRARY` добавить
`category: 'shape' | 'text' | 'own'`.

- `text` → `text`
- `shape`, `circle`, `arrow`, `frame`, `line`, `bracket`, `callout` → `shape`
- `image`, `video` → `own`

`panels/InsertPanel.tsx`: принимает `category` и фильтрует по нему.

**ОГРАНИЧЕНИЕ, ЗА КОТОРОЕ ТЕСТ УЖЕ СТОИТ.**
`test/library.test.ts:123-152` читает исходник `InsertPanel.tsx` с диска
и падает, если id или подпись заготовки встречаются в разметке. Значит
списка «что в какой категории» в JSX быть не может — только фильтр по
переданному значению. Тест обязан остаться зелёным без правок.

Дописать в `library.test.ts`: у каждой записи категория из трёх
допустимых; в каждой категории есть хотя бы одна запись.
*Что сломается, чтобы покраснел:* забытая категория у новой заготовки —
она молча исчезнет из всех панелей.

### C. Сетка, рельс и удаление «смотрю» (`Editor.tsx`, `styles.ts`)

1. `.ed-main` — четыре колонки из §1 через переменные.
2. Слева смонтировать `CatalogRail` и `CatalogPanel`; состояние выбранной
   категории — в `Editor.tsx`.
3. Правая колонка: `ElementList`, удаление, извещения, `SlidePanel`,
   `SegmentPanel`, `MarkPanel`.
4. **Удалить** `<div className="ed-watch">` с `WatchStage`
   (`Editor.tsx:1285-1290`), импорт и стили `.ed-watch*`.
   Перед удалением файла `stage/WatchStage.tsx` проверить, не импортирует
   ли из него `track/SlideStrip.tsx` (там ссылка в комментарии на строке 309 —
   **убедиться грепом**, что это только комментарий).

### D. Полоса свойств: `ArrangeBar` → `PropBar`

`stage/ArrangeBar.tsx` → `stage/PropBar.tsx`.

- высота 38 → **56** (`styles.ts:217`);
- слева поля стиля выделенного, состав из `fieldsFor(type)`
  (`state/style.ts:234`), а на полосу — только частые:
  текст → шрифт, кегль, насыщенность, цвет, выравнивание;
  картинка → скругление; фигура → фон, скругление;
- при нескольких выделенных — пересечение по типам, как в каркасе;
- дальше существующие двенадцать кнопок расположения без изменений;
- справа «Положение» и «Ещё…» — открывают панель «Объект» слева;
- `data-testid` меняется `arrange-bar` → `propbar`, `aria-label`
  «Расположение» → «Свойства объекта». Ссылки в `e2e/arrange.spec.ts`
  поправить: это переименование предмета, а не подгонка теста;
- остановка всплытия нажатий сохраняется (журнал С29 §7).

### E. Панель «Объект»

`Inspector` целиком переезжает в тело `CatalogPanel` при выбранной
категории `object`. На рельсе кнопки нет: без выделения панель
бессмысленна. `data-testid="inspector"` сохраняется — меняется путь к нему,
и e2e, которые его ищут, обязаны сперва открыть панель.

### F. Сворачивание и сжатие

- у панели каталога и у правой колонки — кнопка сворачивания на границе,
  видимая **всегда** (не появляется по наведению: появляющийся под курсором
  орган управления — ровно дефект С29 §8);
- свёрнутая панель даёт своей переменной ширины `0`; рельс остаётся;
- `Splitter` тянет ширину в пределах: каталог 260…560, правая 200…420;
- состояние (свёрнута ли, ширина) хранится в `localStorage` под
  **отдельным ключом**, не в проекте: инвариант №7 про схему сюда не
  относится, и правки схемы не происходит;
- автосворачивания по ширине окна НЕ делаем — незапрошенная гибкость.

### G. Тесты и приёмка — за мной

## 5. Главный риск и чем он закрыт

**Масштаб сцены меняется сильнее, чем за шесть прошлых сессий**
(480 → 760 px). Журнал С29 §10: порог прилипания задан в экранных
пикселях, значит в единицах сцены зависит от масштаба, а масштаб — от
раскладки. Любое число в единицах сцены в тесте прилипания верно ровно
для одной раскладки окна.

Защита уже стоит: Сессия 29 переписала тест так, что мишень **ищется
перебором** с запасом в два порога. Эта сессия — первая настоящая проверка
той защиты. Если тест покраснеет, виноват тест, а не продукт, и чинится
он расширением перебора, а не подгонкой числа.
