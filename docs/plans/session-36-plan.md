## 3. Ядро задачи: ОДНА формула в две стороны

### 3а. Почему не «повернуть дельту»

Промпт Сессии 36 предсказывал главную новую арифметику так: «дельту
жеста придётся повернуть на минус угол группы». Это верно по существу
и **неверно по месту**: поворот дельты чинит только перетаскивание
и ничего не говорит про ресайз, поворот и прилипание.

Дешевле и надёжнее перевести не дельту, а **состояние целиком**:

```
toSceneState(group, child) → состояние ребёнка в координатах СЦЕНЫ
toLocalState(group, scene) → обратно в координаты группы
```

С этой парой весь существующий жестовый код работает **без единой
правки**: `moveBox`, `resizeBox`, прилипание, рамка выделения — все
считают в координатах сцены, а ребёнок внутри повёрнутой группы для
них просто бокс с углом «угол группы плюс свой».

Поворот дельты при этом никуда не девается — он **выводится**:

```
toLocal(g, S + d) − toLocal(g, S) = R(−θ)·d
```

то есть ровно «дельта, повёрнутая на минус угол группы». Мы получаем
её следствием проверенной формулы вместо того, чтобы писать вторым
описанием того же факта.

### 3б. Формула уже написана и уже проверена

`ungroupElements` (`groupElements.ts:205-224`) делает `toSceneState`
для каждого ребёнка каждого слайда. Это не «похожая» арифметика,
а буквально та же:

```
центр_без_поворота = (g.x + c.x + c.w/2,  g.y + c.y + c.h/2)
центр_на_сцене     = rotate(центр_без_поворота, центр(g), g.rotation)
угол               = g.rotation + c.rotation
```

Значит первый срез — **извлечение, а не написание**: `toSceneState`
выносится, `ungroupElements` начинает её звать. Круговой тест сборки
и разборки, который в С35 оказался единственной защитой от потери
углового слагаемого, продолжает охранять её же.

Обратная сторона:

```
центр_без_поворота = rotate(центр_на_сцене, центр(g), −g.rotation)
x_локальный        = центр_без_поворота.x − g.x − w/2
угол_локальный     = scene.rotation − g.rotation
```

### 3в. Где живут

`stage/geometry.ts` — там уже `rotate`, `unionBox`, `hitTest`, и
`groupElements.ts` уже импортирует оттуда. Направление зависимостей
сохраняется, второго места с той же арифметикой не появляется.

## 4. «Внутри группы» — это НЕ новое состояние

Заманчиво завести `activeGroupId` рядом с выделением. Не надо: оно
**выводится из выделения** и без единого нового поля.

```
активная группа = общий parentId всех выделенных,
                  если он один и не undefined
```

Почему так лучше, а не короче:

- **отмена не рассинхронизируется.** `selectedIds` лежит в состоянии
  истории (`Editor.tsx:147`). Отдельное поле «внутри» пришлось бы либо
  тоже класть в историю, либо мириться с тем, что Ctrl+Z вернёт
  выделение верхнего уровня, а редактор останется «внутри»;
- **выход не надо программировать отдельно.** Escape уже снимает
  выделение (`Editor.tsx:1445`), щелчок по пустому месту тоже — обе
  дороги дают «выделено ничего» и, значит, «снаружи», по построению;
- **щелчок по чужому объекту выходит сам:** выделение стало верхнего
  уровня — активной группы больше нет.

Опасность у этого решения ровно одна, и её надо назвать: выделение
нескольких детей РАЗНЫХ групп дало бы «снаружи» при том, что автор
видит выделенных детей. Сегодня такое выделение недостижимо (обвести
рамкой можно только кандидатов, а кандидаты — дети одной активной
группы). Правило пишется сразу, вместе с проверкой, а не когда данные
окажутся молча допущены.

## 5. Кандидаты на попадание, пока автор внутри

`visibleLayers` (`StageView.tsx:625-652`) перестаёт быть «все верхнего
уровня» и становится:

| где автор | кандидаты |
|---|---|
| снаружи | элементы верхнего уровня (как сейчас) |
| внутри группы G | дети G, **приведённые к сцене**, плюс элементы верхнего уровня, кроме самой G |

Отсеивание заменяется приведением — именно этого требует «Чего НЕ
делать» промпта: просто перестать отсеивать значило бы вернуть призрака
из журнала §14.

Три потребителя получают верное поведение **по построению**, без
отдельных правил (тот же приём, что дал побочную выгоду в §14 С35):

- попадание указателя (`:662`) — щелчок берёт брата, а не группу;
- прилипание при перетаскивании (`:1034`) и при ресайзе (`:1073`) —
  ребёнок прилипает к братьям и к чужим объектам сцены;
- обведение рамкой (`:1145`) — обводится содержимое группы.

## 6. Двойной щелчок: как он уживается с правкой текста

Двойной щелчок уже занят входом в правку текста (`StageView.tsx:1240`).
Развилка решается тем, где автор находится:

| положение | двойной щелчок по тексту |
|---|---|
| снаружи, текст верхнего уровня | правка текста (как сейчас) |
| снаружи, текст внутри группы | **вход в группу**, текст выделен |
| внутри этой группы | правка текста |

То есть внутрь группы с текстом автор попадает двумя двойными
щелчками, как в Канве. Одиночный щелчок снаружи по-прежнему берёт
группу целиком.

## 8. `reflowGroup` — второй вызывающий, обещанный С35

Правка ребёнка меняет охват группы. Функция уже есть, но зовётся из
одного места (сборка). Теперь у неё появляется настоящий второй
вызывающий — ровно то условие, при котором С35 разрешила её извлечение.

**Мина: у повёрнутой группы пересчёт охвата двигает центр вращения.**
Дети вращаются вокруг центра группы; изменив бокс, мы двигаем центр,
и всё содержимое уезжает на экране. Наивный пересчёт «взять охват
и записать» ломает картинку тем сильнее, чем больше угол — и на
неповёрнутой группе (то есть на всей фикстуре `groups.json`) ведёт
себя безупречно.

Разрешается тем, что порядок действий ставится правильно:

1. снять состояния детей **на сцене** (`toSceneState`) — это истина,
   которую обязано сохранить всё остальное;
2. охват детей в ЛОКАЛЬНОЙ системе группы → `u` (через `unionBox`,
   он считает по углам, значит собственные повороты детей учтены);
3. новый бокс группы: размер `u`, а положение — так, чтобы видимый
   центр нового охвата совпал с тем, где он виден сейчас:
   `центр' = rotate(центр_u, центр_старый, угол)`;
4. новые локальные координаты детей = `toLocalState(группа', сцена)`
   из пункта 1.

Пункт 4 делает правильность **следствием построения**, а не удачи:
дети ставятся туда, где они были видны, каким бы ни вышел новый бокс.

**Зовётся на завершении жеста, а не на каждом кадре.** Живой пересчёт
дал бы обратную связь: жест держит стартовые боксы, а группа под ним
меняет систему координат. Видимая цена — бледная рамка догоняет
содержимое на отпускании, а не тянется за ним. Названо здесь вслух,
чтобы не выглядело недосмотром.

## 10. Зазор вокруг сцены — отдельная задача, после групп

### 10а. Замер СДЕЛАН 12.08.2026

`docs/research/2026-08-12-canva-stage-gap.md`.

**16 px по вертикали, 24 px по горизонтали.** Литеральные пиксели
в инлайн-объявлении `padding: 16px 24px`, а не доля от окна — проверено
самим объявлением, потому что вычисленный стиль процент от константы
не отличает.

Вписывание Canva считает от области ЗА ВЫЧЕТОМ зазора:
`(735 − 2·16)/1080 = 0.6509`, подпись показывает 65 %. Три числа сошлись.

Отдельно от зазора Canva резервирует 48 px сверху и 88 снизу под свою
хромировку. У нас это полоса свойств и `ed-zoom-strip`, они уже есть
и предметом задачи не являются.

Наши ручки — 10 px с `margin: -5px`, выступают за рамку на 5. Зазор
16 px даёт 11 px запаса сверх ручки, то есть дефект С34 закрывает
с большим запасом.

**Насколько мельче станет наша сцена при «Вписать» — посчитать прогоном**
в срезе 4, а не оценивать. Прикидка «3 %», названная владельцу при выборе,
замером не является.

### 10б. Где правится — и почему инвариант №5 не страдает

`fitStage` живёт в плеере (`render.ts:83`) и зовётся плеером же. Зазор —
понятие **редактора**: зритель видит сцену во весь экран, поля ему
не нужны. Значит формула вписывания не трогается вовсе — редактор
передаёт в неё **уменьшенный размер окна**:

```
StageView.tsx:368  fitStage(host.clientWidth − 2·ЗАЗОР,
                            host.clientHeight − 2·ЗАЗОР, stage)
```

Второй реализации летербокса не появляется, инвариант №5 остаётся цел.
`canvasSize` (`zoom.ts:99`) обязан сохранить поле при вписывании.

### 10в. Что покраснеет, и это сигнал, а не поломка

- `e2e/stage-controls-reachable.spec.ts`: `knownUnreachable` для
  `demo/bg` — сегодня `['ручка s','ручка se','ручка sw']`, станет
  пустым. Список **обновить**, не обнулять «на всякий случай»: пустой
  список у ВСЕХ случаев выключил бы проверку;
- e2e «полотно равно окну холста»;
- **скриншотных эталонов РЕДАКТОРА не существует, и зазор не трогает
  ни одного из 95.** Посчитано, а не оценено: все 95 сняты
  `fixtures.spec.ts` со страницы `preview.html` (строка 93), то есть
  с ПЛЕЕРА, по пять на каждую из 19 фикстур. `toHaveScreenshot` больше
  нигде в `e2e/` не встречается; `shots.spec.ts` — оснастка съёмки,
  сравнения не делает.

  Это опровергает опасение, записанное в этот план раньше и названное
  владельцу вслух. Зазор — правка редактора, плеер не затронут, значит
  эталоны не двигаются. Проверить всё равно прогоном: если хоть один
  покраснеет, значит зазор просочился в плеер, и это будет нарушением
  инварианта №5, а не поводом обновить эталон.

## 11. Тесты, и чем каждый краснеет

Для каждого назван слом. Тест без ответа на «что должно сломаться» —
декоративный.

| тест | краснеет от |
|---|---|
| круговой `toScene → toLocal` | потери любого слагаемого; **фикстура обязана иметь ненулевой угол И у группы, И у ребёнка** |
| `toSceneState` против `ungroupElements` | расхождения двух описаний одной формулы |
| ~~`reflowGroup` сохраняет сцену~~ | **НИЧЕГО. Тест пуст, вычеркнут — см. §10 журнала.** `childBoxInScene` обратна `childBoxInGroup` для ЛЮБОГО бокса группы, значит проверка сводится к тождеству и зелена при любой реализации |
| `reflowGroup` даёт верный бокс ГРУППЫ (числа с бумаги) | выброса поворота вокруг старого центра |
| `reflowGroup` даёт плотный охват | пропуска пересчёта локальных координат |
| e2e: двойной щелчок берёт ребёнка | возврата фильтра `parentId === undefined` |
| e2e: тяга ребёнка в ПОВЁРНУТОЙ группе | отсутствия поворота дельты; **на неповёрнутой группе слом невидим** |
| e2e: Escape и щелчок по пустому выходят | потери вывода активной группы из выделения |
| e2e: бледная рамка исчезает после выхода | того, что рамка рисуется по группе, а не по активности |
| e2e: ручки достаются у элемента во весь экран | отката зазора |

**Повёрнутая группа в e2e — без новой фикстуры.** У группы есть ручка
поворота, и она работает (`stage-controls-reachable.spec.ts:184`). Тест
поворачивает группу жестом, потом заходит внутрь и тянет ребёнка. Новая
фикстура стоила бы пяти новых скриншотных эталонов; поворот жестом —
ноль, и заодно проверяет настоящий путь автора.

Юнитам фикстура не нужна вовсе: данные пишутся в тесте, углы ненулевые
у обоих.
